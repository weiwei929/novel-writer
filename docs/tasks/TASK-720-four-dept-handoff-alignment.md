## 一、 方案目标

彻底对齐 **创意组、企划课、创作室、编审部** 四大生产部门的流转模型，统一贯彻以下分层范式：

> **「Worker 部门内完工（封盘归入右列已完成库） → Manager 跨部门把关（带二次确认交接投递至下一部门） → 投递后在本部门保留灰色只读交接留痕（业绩留档）」**

消除以前创意组跳过“组内完工库”直接投递的逻辑盲点，强化跨部门交接时的命名规范、视觉统一、二次确认防线与交接留痕机制。

---

## 二、 跨部门流转关口统一规范

### 1. 命名与视觉规范
* **统一按钮命名**：所有跨部门关口按钮命名统一为 **「提交至 xxx」**：
  * 创意组 → 企划课：🟢 **「提交至企划课」**
  * 企划课 → 创作室：🟢 **「提交至创作室」**
  * 创作室 → 编审部：🟢 **「提交至编审部」**
  * 编审部 → 文集库：🟢 **「提交至文集库」**
* **统一按钮视觉**：跨部门关口按钮一律使用**绿色高亮按钮**（`bg-emerald-600 hover:bg-emerald-700` 或 `bg-green-600`，带图标）。
* **统一二次确认文案**：在点击绿色按钮弹出的二次确认窗口（`HandoffConfirmModal`）中，统一配有标准文案：
  > **“此作品将提交至 [目标部门]，请在后续阶段进行处理”**

---

### 2. 部门内交接留痕规范 (0608 §7.1 业绩留档)
作品跨部门提交给下游后，**不从本部门的“已完成”列表中直接抹除**，而是保留在原部门作为部门业绩留档：
* **留痕视觉**：呈现**灰色/淡化卡片**，隐藏绿色提交按钮，标注提交状态与时间戳（如：`已提交至企划课 · 2026-08-03 11:30`）。
* **只读防篡改**：留痕项只供查阅与留档，不参与在办/待办计数，防止跨部门数据双计。

## 三、 具体改动点

### 1. 创意组 (Creative Department)
* **状态控制**：在提案 `status` 中补充 `formed`（或 `completed`）内部完工状态。
* **Worker 操作**：在 `ProposalDetailPage` 中，构思完后点击 **「完成构思」**（常规琥珀色按钮），提案状态变为 `formed`，并移入创意组右侧栏 **《已完成创意作品》** 列表。
* **Manager 操作**：在右侧栏《已完成创意作品》或打开完工提案时，展示绿色 **「提交至企划课」** 按钮，点击后弹出二次确认弹窗，提示 *“此作品将提交至企划课，请在后续阶段进行处理”*，确认后投递给企划课。
* **交接留痕**：投递后，卡片保留在右侧栏，变为灰色只读，显示 `已提交至企划课` 标签与时间戳。

### 2. 企划课、创作室、编审部 (Planning / Studio / Editorial)
* 统一将跨部门操作按钮动词重命名为 **「提交至 xxx」** 并提升为 **绿色高亮风格**。
* **统一二次确认弹窗 (`HandoffConfirmModal`)**：
  * 在企划课点击 `提交至创作室` 时，提示 *“此作品将提交至创作室，请在后续阶段进行处理”*。
  * 在创作室点击 `提交至编审部` 时，提示 *“此作品将提交至编审部，请在后续阶段进行处理”*。
  * 在编审部点击 `提交至文集库` 时，提示 *“此作品将提交至文集库，请在后续阶段进行处理”*。
* **交接留痕挂载**：确认提交后，作品在原部门“已完成”列表中保留为灰色只读卡片 + 时间戳展示，不从页面彻底消失。
