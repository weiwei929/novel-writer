## 一、目标形态（五部门统一）

```text
┌─ 待 X ────────┬─ X 中 ────────┬─ 已完成 X ─────────────────────┐
│               │               │  未提交 → 可点「提交至 Y」      │
│  [开始 X]     │  [完成 X]     │  已提交 → 灰色只读 + 交接时间戳 │
└───────────────┴───────────────┴────────────────────────────────┘
     阶段内          阶段内            跨阶段唯一出口 + 留痕
```

### 关键推论：「留痕」不是附加功能，是「已完成」段的正确形态

司令官条目 7 要求「已完成未提交可点提交；点后变色转只读，显示时间戳」。

按准则重读——**这就是"已完成"段本来该有的样子**：

- 作品**推走后不消失**，留在原段变灰 → 满足「推完之后留痕」
- 时间戳可见 → 满足「每个阶段的工作留痕」
- 已提交项不可再操作 → 满足「不回头」

> **因此原计划的 710-G（交接留痕）不单列**，并入各部门归位卡。
> 否则 E′ 做完后，"已完成"段的过滤仍是 `!已提交`，已提交项照旧消失——**又是半成品**。

## 四、方案实施后，下一轮测试的已知风险 ★

**这一节回应司令官"要考虑下一步测试中可能的问题"。**

| # | 风险 | 说明 | 预置对策 |
|---|---|---|---|
| R1 | **历史数据归段** | 现库 4 条 `conceiving` 提案、0 条 `origin`。三段化后它们全落"构思中"，其中填齐必填的应进"已完成构思" | 归段按**当前字段值实时判定**，不写状态字段 → 无需迁移 |

| R3 | **物化提前不回溯** | 已放行过的老作品不会补生成章节 | 明确不回溯；测试时用新作品验，不拿旧作品当反例 |
| R4 | **"已完成构思"卡在半截** | 用户只填标题没填梗概 → 永远停在"构思中"，且**没有提示缺什么** | 「构思中」段卡片需显示"还差：故事梗概"——否则用户不知道为什么推不出去 |
| R5 | **留痕导致列表无限增长** | 已提交项永久留在"已完成"段 | 本轮不做折叠/归档，但需在方案中承认；作品量大后再议 |
| R6 | **摘除详情页按钮后动线变长** | 用户在详情页填完，要退回列表才能提交 | 只读提示必须**明确指路**（"可到企划课列表提交"），且列表入口一键可达 |
| R7 | **企划课「开始企划」是新增动作** | 此前靠上游代劳，现在多一次点击 | 属预期成本，写入方案供司令官确认 |
