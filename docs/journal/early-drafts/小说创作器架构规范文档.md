## 架构概述

### 项目定位
小说创作器是一个面向个人创作者和小型创作团队的云端写作平台，提供创作、编辑、管理和发布功能。

### 核心价值
1. **专注创作**：简洁的界面设计，减少干扰
2. **智能辅助**：AI驱动的写作建议和内容生成
3. **数据安全**：本地存储与云端备份结合
4. **灵活组织**：支持文集、项目和章节的多级管理

### 架构原则
1. **模块化**：各功能模块独立，便于维护和扩展
2. **一致性**：前后端类型定义、API设计、错误处理保持一致
3. **可扩展性**：支持未来功能扩展和性能优化
4. **安全性**：保护用户数据安全，防止未授权访问

## API设计

### 基础规范
- **基础URL**：`/api/v1`
- **响应格式**：统一使用 `ApiResponse<T>` 格式
- **错误处理**：统一错误码和错误消息
- **认证**：使用Bearer Token认证

### 响应格式
```typescript
interface ApiResponse<T = any> {
  success: boolean
  data?: T
  error?: {
    code: string
    message: string
    details?: any
  }
  pagination?: {
    total: number
    page: number
    limit: number
    totalPages: number
  }
  metadata?: {
    timestamp: string
    version: string
    [key: string]: any
  }
}
```

### 中间件
```typescript
// middleware/errorHandler.ts
export const errorHandler = (err: any, req: Request, res: Response, next: NextFunction) => {
  console.error('Unhandled error:', err)
  res.status(500).json({
    success: false,
    error: {
      code: 'INTERNAL_ERROR',
      message: process.env.NODE_ENV === 'production' ? '内部服务器错误' : err.message
    }
  })
}

// middleware/responseHandler.ts
export const sendSuccess = <T>(res: Response, data: T, metadata = {}) => {
  const response: ApiResponse<T> = {
    success: true,
    data,
    metadata: {
      timestamp: new Date().toISOString(),
      version: '1.0.0',
      ...metadata
    }
  }
  
  res.json(response)
}

export const sendError = (res: Response, code: string, message: string, statusCode = 500) => {
  const response: ApiResponse = {
    success: false,
    error: { code, message }
  }
  
  res.status(statusCode).json(response)
}
```

## 开发流程管理规范

### 环境准备与端口管理

#### 端口分配标准
- **前端开发服务器**：3000 (Vite Dev Server)
- **后端API服务器**：5000 (Express Server)
- **数据库服务**：如使用独立数据库，端口 5432 (PostgreSQL) 或 27017 (MongoDB)
- **测试环境前端**：3001
- **测试环境后端**：5001

#### 端口冲突检查与清理
开发前必须检查并清理端口占用：

```bash
# Windows PowerShell 端口检查
netstat -ano | findstr :5000
netstat -ano | findstr :3000

# 如发现占用，记录进程ID并终止
tasklist | findstr <PID>
taskkill /F /PID <PID>

# 或使用PowerShell一键清理
Get-Process -Id (Get-NetTCPConnection -LocalPort 5000).OwningProcess | Stop-Process -Force
Get-Process -Id (Get-NetTCPConnection -LocalPort 3000).OwningProcess | Stop-Process -Force
```

#### 服务启动顺序
1. **数据库服务**（如使用）
2. **后端API服务器** (`cd backend && npm run dev`)
3. **前端开发服务器** (`cd frontend && npm run dev`)

#### 环境变量配置

#### 代码变更工作流程
1. **功能开发前**
   - 确保本地环境干净（无未提交变更）

2. **开发过程中**
   - **架构优先**：重大功能先完善架构设计，避免"头痛医头"

   - **测试驱动**：核心功能优先编写测试用例
   - **文档同步**：API变更立即更新文档

3. **功能完成后**
   - 运行完整测试套件
   - 检查代码规范合规性
   - 提交PR并请求代码审查
