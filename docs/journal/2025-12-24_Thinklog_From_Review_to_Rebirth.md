## 2. Staging Pool：从无到有的完整实现

### 为什么需要 Staging Pool？

在 Cursor 审查之前，我们的导入流程是"一步到位"的：
```
用户上传文件 → 解析 → 直接写入数据库 → 跳转到项目列表
```

这有什么问题？
1. **不可逆**：一旦导入，数据就写死了，用户无法预览或修改。
2. **不透明**：用户不知道解析出了什么，章节标题对不对，内容有没有丢失。
3. **不友好**：如果解析有误，用户只能删除项目重新导入。

### 我们的解决方案

设计了完整的 **Staging → Preview → Confirm** 三段式流程：

```
导入文件 → 暂存到内存 → 预览页面（可编辑） → 用户确认 → 正式创建项目
```

**技术实现**：
- 后端：`/api/import/stage` 和 `/api/import/confirm` 两个端点
- 前端：`ImportPreviewPage` 组件，支持编辑项目标题、章节标题
- 状态管理：使用 `sessionStorage` 暂存数据，避免刷新丢失

**成果**：用户现在可以在导入后看到完整的预览，确认无误后再"转入创作"。这不仅提升了体验，更体现了**"用户掌控感"**的设计哲学。

## 3. 导入流程的 Bug 修复马拉松

在实现 Staging Pool 后，我们开始了大量的测试，并陆续发现和修复了多个 Bug：

### Bug #1: 章节解析过于严格
- **现象**：一些格式稍有不同的 Markdown 文件被判定为"未找到有效章节"
- **原因**：正则表达式要求标题必须严格符合 `# 第X章 标题` 格式
- **修复**：放宽了正则，支持更多变体（如 `## 章节名`、`# 1. 标题` 等）

### Bug #2: 短章节被误杀
- **现象**：内容少于 100 字的章节被自动过滤
- **原因**：过于保守的内容长度验证
- **修复**：降低最小长度要求，并改进了"空章节"的判断逻辑

### Bug #3: 状态管理混乱
- **现象**：导入成功但 UI 显示不一致
- **原因**：成功/失败的状态更新时机不当
- **修复**：统一了状态管理，确保 UI 与数据同步

## 4. AI 元数据提取：最激烈的战斗

这是今天的**重头戏**。用户在测试 AI 元数据提取功能时，发现了一个诡异的问题：

**现象**：
- 点击"启动 AI 协助"
- AI 成功生成元数据
- 弹出确认模态框
- 点击"确认并保存"
- **报 404 错误！**
- 但数据库中数据已经保存了

### 第一轮排查：后端响应格式

我们首先怀疑是后端路由问题。检查后发现，`/api/projects/:id/confirm-metadata` 端点的响应格式不一致，有些地方返回的是普通对象，而不是标准的 `ApiResponse`。

**修复**：统一使用 `reply.send(ApiResponse.success(...))`。

### 第二轮排查：前端状态同步

404 依然存在。我们转向前端，发现 `MetadataReviewModal` 的 `editedMetadata` 状态只在组件首次渲染时初始化，不响应 `extractedMetadata` prop 的变化。

**修复**：添加 `useEffect` 监听 prop 变化并同步状态。

### 第三轮排查：双重提交的真相

404 **还是存在**！这时用户提出了一个关键观察：

> "我觉得问题在于，确认弹窗的位置可能不对。应该是 AI 提取后不保存，弹窗确认后再保存。"

这句话点醒了我。我仔细检查代码，发现了**惊人的真相**：

```typescript
// MetadataReviewModal 内部
const handleConfirm = async () => {
  await projectsApi.confirmMetadata(projectId, true, editedMetadata)  // 第一次调用
  onConfirm()  // 触发外部回调
}

// EnhancedEditorPage 中
onConfirm={() => {
  handleMetadataConfirm(true)  // 第二次调用！
}}

const handleMetadataConfirm = async (confirmed) => {
  await projectsApi.confirmMetadata(projectId, confirmed)  // 又调用了一次！
}
```

**双重提交！**
- 第一次调用成功，`_draft` 被移动到正式字段并清除
- 第二次调用时，`_draft` 已经不存在了
- 后端返回 400："没有待确认的元数据"
- 前端误以为是 404

**修复**：移除外部的重复调用，只保留模态框内部的 API 调用。

### 深度优化：从"能用"到"好用"

在修复 Bug 后，用户提出了体验优化需求：

**问题 1**："AI 正在生成..." 提示一闪而过，不知道发生了什么。

**解决方案**：
- 添加 `isAIAnalyzing` 状态
- 显示持续的蓝色 Loading 横幅："AI 正在深度阅读并分析您的作品，请稍候..."
- 从点击到模态框弹出全程可见

**问题 2**：保存后不知道去哪里查看元数据。

**解决方案**：
- 优化成功通知文案
- 明确告知："AI 分析结果已应用。您随时可以在顶部的'项目元数据'面板中查看和修改。"
