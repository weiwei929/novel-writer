## §0 创意组在 0608 模型中的定位

创意组是整条管线的起点。与其它 4 个部门不同，创意组管理的对象是 **Proposal**（提案），而非 **Project**（作品）。这是因为提案尚未进入正式的立项流程。

创意组的上游是灵感采集工具（灵感手记/外来参考/作品构思中），下游是企划课的"接收入企划课"动作。

## §1 创意组三层映射

### 1.1 三层模型

> **修正案对齐**：本节采用 `0608-supplement-creative-discovery.md` 的三层模型。旧的 Proposal 三工作区映射（`creating/created/approved`）不再作为 P4 实施依据。

| 创意组层级 | 状态/实体 | 上下文标签 | 含义 |
|-----------|-----------|-----------|------|
| 素材层 | FileReference / Scrap(source=creative) / AI 搜索 | 素材 | 外来参考、灵感碎片和搜索结果，只读引用 |
| 进行中 | CreativeFlow | 作品构思中 | 作者围绕素材进行构思讨论，可反复迭代 |
| 已完成 | Proposal.status = `created` | 提案停留 | 已从构思中提炼成型，等待三选一 |

### 1.2 与 v4.1 4 Tab 的关系

0608 不废除创意组的 4 Tab 布局，而是在其之上叠加三层语义：

| 现有 Tab | 0608 三工作区解释 |
|---------|------------------|
| 灵感手记 | 素材层：Scrap(source=creative) |
| 外来参考 | 素材层：FileReference |
| 作品构思中（原"创意讨论"） | 进行中：CreativeFlow |
| 企划建议书 | 已完成：Proposal(created)，前端标题可改为"提案停留" |
| AI 搜索 | 素材层：AI 搜索结果 |

### 1.3 创意组链路改造

当前 `creative/proposals` 页面展示所有提案。按三层模型应调整为：

```
┌─ 企划建议书 ─────────────────────────┐
│                                        │
│  ├ 素材层                              │
│  │   └ 外来参考 / 灵感碎片 / AI 搜索    │
│  │   └ 动作：查看 / 引用到构思          │
│  │                                      │
│  ├ 作品构思中（CreativeFlow）           │
│  │   └ 正在进行的构思讨论              │
│  │   └ 动作：[继续构思] [提炼为提案]    │
│  │                                      │
│  └ 提案停留（Proposal.created）         │
│      └ 已提炼成型的提案                │
│      └ 动作：[提交企划课] [暂存] [退回构思] │
└────────────────────────────────────────┘
```

**当前阶段：P4 实施必须以此三层链路为准。**

## §2 创意组的关键动作

### 2.1 提炼为提案

`CreativeFlow → Proposal(created)`

- **触发**：用户在作品构思中列表点击"提炼为提案"
- **效果**：从 CreativeFlow 生成 Proposal(`created`)
- **发生位置**：作品构思中列表条目
- **性质**：流程决策，不在详情页隐式触发

### 2.2 提交企划课

Proposal(`created`) → 企划课待处理

- **触发**：用户在提案停留列表点击"提交企划课"
- **端点**：`POST /proposals/:id/submit`（目标端点）
- **发生位置**：提案停留列表条目
- **性质**：流程决策，不改变提案核心内容

### 2.3 企划课接收（跨部门接收）

Proposal 已提交 → Project(planning)

- **触发**：企划课待处理列表点击"接收入企划课"
- **端点**：`POST /proposals/:id/accept-into-planning`
- **效果**：创建 Project(planning)，保留 Proposal 来源

### 2.4 提案暂存（替代 reject）

- **走文件暂存池**：`POST /proposals/:id/soft-delete`（🎯 目标端点，Commit 1+）
- **发生位置**：提案停留列表条目
- **注意**：不走 `reject`（F-002 冻结）

### 2.5 退回构思

- **触发**：创意组提案停留列表点击"退回构思"
- **效果**：Proposal(created) 回到作品构思中
- **性质**：部门内退回，合规

企划课不能把提案退回到创意组。争议走文件暂存池线外裁决。

## §3 创意组的 0608 合规检查

| 原则 | 检查 | 状态 |
|------|------|------|
| 不允许跨部门退回 | 企划课不退回创意组 | ✅ 已在冻结清单 F-001 |
| reject 用户路径冻结 | 不放 reject 按钮 | ✅ F-002 已冻结 |
| shelved 字面量冻结 | Proposal 不设 `shelved` | ✅ 不涉及 |
| 全局线性推进器冻结 | 不使用 StageTransitionModal | ✅ 创意组不涉及 |
| 部门上下文标签 | Proposal 标签维持现有 | ✅ 不要求变更 |
| 内容变化≠流程推进 | 构思详情只保存内容，提炼/提交/暂存/退回在列表上 | ✅ 修正案对齐 |
| 确认完成≠放行 | 提案提炼≠提交企划课≠企划课接收 | ✅ 三步分离 |

## §5 与其它部门设计文档的关系

创意组的实施在 0608 设计体系中处于低优先级，因为：

1. 创意组在 v4.1 中已完成交付（4 Tab 可用）
2. 0608 对创意组的影响主要是冻结项（reject、跨部门退回）的合规检查
3. 创意组的三工作区改造是可选优化，不阻塞管线

**实施优先级**：✅ P4（企划课→创作室→编审部→文集库之后）
