## 一、这是什么

一个**本地优先的中文小说创作工具**。数据存在你自己电脑的 SQLite 里，不上云。

核心主张是把小说创作拆成有先后的几步——先想清楚设定，再规划章节，最后才进编辑器写正文——而不是打开一个空白文档硬写。

**它首先是一个学习项目。** 记录多、过程复杂，是刻意的：作者用它来学习软件工程与 AI 协作。这一点决定了本仓库的文档策略（见第六节）。

## 二、现在能做什么

### ✅ 可用

| 能力 | 说明 |
|------|------|
| 文集 / 作品管理 | 分组、看板、状态流转 |
| 企划课 | 作品设定（人物、时空、事件、风格）、章节规划、发布门槛校验 |
| 企划 → 创作室交接 | 设定确认后一键生成章节骨架 |
| 创作室 | 三栏编辑器（Monaco）、正文保存、字数统计 |
| 本地草稿保护 | 断网/异常时自动镜像，一键恢复 |
| 只读参阅侧栏 | 写作时对照设定与本章梗概 |
| Markdown 导入导出 | — |
| 单用户登录 | 会话令牌 |

**主链路**（已实测跑通）：

```text
创意 → 企划课（设定 + 章节规划）→ 确认 → 交接创作室 → 写正文
```

### ⛔ 冻结（代码在，入口关闭）

| 能力 | 冻结方式 |
|------|----------|
| **全部 AI 功能** | `frontend/src/config/aiFreeze.ts` 中 `AI_UI_FROZEN = true`，界面统一显示「AI 集成开发中」。后端 `AIService` / `ContextManager` / `PromptManager` 保留未删，随时可解冻 |
| 旧版世界观 / 人物 / 故事线 | 仅折叠展示，不再扩展。新内容一律写入「作品设定」 |

> ⚠️ **注意**：仓库里若干旧文档写着「AI 95% 完成」「状态：已实现」，指的是**代码写完了**，不是**能用**。
> **对外可用的 AI 能力为 0。** 判断进度以本文为准。

### ⚠️ 已知短板

| 短板 | 影响 |
|------|------|
| 前端无自动化测试 | 后端有 16 个用例，前端 2.3 万行零覆盖。改前端只能靠肉眼验收 |
| 服务监听 `0.0.0.0` + 密码有硬编码兜底 | 同一 WiFi 下他人可访问，默认密码印在 README 里 |
| 字数统计三处取值不一致 | 标题栏、底栏字符数、词数互相矛盾；中文按空格分词无意义 |
| 登录态易失 | 会话文件路径写死 POSIX `/tmp`，Windows 下写入失败被静默吞掉，后端一重启就要重新登录 |
| Monaco 加载源未定 | 编辑器内核疑似运行时从 CDN 拉取，若属实则「离线可用」不成立（**待验证**） |

## 三、技术形态

| 层 | 选型 |
|----|------|
| 前端 | React 18 + TypeScript + Vite + TailwindCSS + Monaco Editor + Zustand |
| 后端 | Fastify 5 + TypeScript + Prisma 6 + SQLite + Zod |
| 接口 | REST，前缀 `/api/v2` |
| 认证 | 会话令牌（单用户） |
| 规模 | 前端 ~2.3 万行 / 后端 ~5.4 千行 |

**设定与章节规划存在 `Project.metadata` 这个 JSON 字段里**，正文存 `Chapter` 表。这是当前数据模型最需要留意的地方：JSON 字段无法建索引、无结构约束，迁移全靠代码兜。

## 四、往哪走

分三期，**每期做完都应是可用状态**，不追求一次到位。

### 第一期 · 把地基坐实（当前）

目标：让现在能用的东西**可靠**，而不是增加新能力。

| 事项 | 规模 | 为什么先做 |
|------|------|-----------|
| 监听地址改回本机 + 设置真实密码 | 两行 | 现在等于门开着 |
| 删除死依赖 `better-sqlite3` / `sqlite3` | 改配置 | 从未被引用，却拖慢每次安装并引发 Windows 文件锁 |
| 字数统计三处对齐，中文按字符计 | 小 | 字数是写作者的核心指标，现在三个数字打架 |
| 会话文件路径改用系统临时目录 | 一行 | 修掉「一重启就掉登录」 |
| 验证 Monaco 加载源并定死 | 小 | 决定「离线可用」这句话能不能说 |
| **修 `backend` 的 `lint` 脚本** —— 改为「client 不存在才 generate」 | 一行 | **已咬三次**（2026-07-25 一次、07-27 两次）。现写死 `npm run generate && tsc --noEmit`，只要 dev 在跑就撞 Windows DLL 锁，类型检查根本跑不到。绕法：`npx tsc --noEmit` |
| 打开被关掉的代码检查规则 | 中 | 详见下方说明 |

> **关于代码检查规则**：当前 eslint 配置几乎是空的——`no-explicit-any`、`no-unused-vars`、`react-hooks/exhaustive-deps` 全部未启用或关闭，所以检查**永远是绿的**。
> 其中 `exhaustive-deps` 专门捕捉自动保存、草稿恢复这类逻辑里的陈旧闭包缺陷，**正是本项目投入最多精力的战场**。把它打开，等于免费获得一道防线。

### 第二期 · 让改动可验证

| 事项 | 说明 |
|------|------|
| 前端最小测试防线 | 只覆盖保存与草稿恢复链路，不追求覆盖率 |
| 复活或重写 E2E 脚本 | 仓库已有 `scripts/baseline-e2e-v01.mjs`（18 KB）+ `scripts/test-api.js`，先确认存废，能用就替代人工点击 |
| 数据模型收口 | 决定 `metadata` JSON 字段的边界；旧数据表定一个删除日期，而不是无限期「逐步降级」 |

### 第三期 · 解冻 AI，或者放弃它

到这一步才回答那个悬着的问题：**这个工具到底要不要 AI？**

- 要 → 解冻，但只上一条最小链路（比如「续写当前段落」），做透再扩
- 不要 → 删掉后端 AI 代码，README 去掉相关叙述，做一个纯粹的结构化写作工具

**现在不必决定，但不要假装已经决定了。** 冻结状态本身是诚实的，写着「95% 完成」才是问题。

### 未列入（明确不做）

- 多用户 / 协作编辑 —— 当前认证与数据层均为单用户假设，改动成本远超收益
- 正文编辑器大改
- 长篇规范类文档的修订

## 五、怎么开工

### 人

```powershell
# 后端
cd backend; npm run dev
# 前端（另开窗口）
cd frontend; npm run dev
```

访问 `http://localhost:3000`。密码见 `backend/.env` 的 `APP_PASSWORD`。

提交前三道门：

```powershell
cd backend;  npm run lint; npm test
cd ..\frontend; npm run lint; npm run build
```

> 后端 `dev` 在跑时**不要**执行 lint / build —— 会触发 `prisma generate` 并撞上 Windows 文件锁。先停 dev。

### AI 工具

读两份即可上手：

1. [`../AGENTS.md`](../AGENTS.md) —— 角色分工与红线
2. [`CURRENT_BASELINE.md`](./CURRENT_BASELINE.md) —— 当前分支、已合并内容、暂不做清单

**再加本文，用于理解方向。** 三份之外的文档，先看它头部的状态行再决定是否采信。

## 六、文档怎么放

2026-07-27 治理后的结构。**分类依据是功能，不是年份。**

| 位置 | 装什么 | 能否作为操作依据 |
|------|--------|-----------------|
| `docs/` 顶层 + `guides/` `specs/` `tasks/` `design/` | 现役：今天还要照着做的 | ✅ 可以 |
| `docs/journal/` | 学习档案：思考、讨论、会诊、复盘、随笔 | ❌ 只作参考，不是指令 |
| `docs/archive/` | 历史归档：已完成的任务卡、里程碑、旧规格 | ❌ 只作溯源 |

### 状态行规则

每份文档标题下应有一行状态标记：

```markdown
> **状态**：现役 · 最后核对 2026-07-27
> **状态**：学习记录 · 不作为操作依据
> **状态**：⛔ 已冻结 · 设计留档
> **状态**：历史 · 已由 XXX 取代
```

**无状态行的文档，不得作为操作依据。**

这条规则的意义在于：状态标记**跟着文件走**。文件被移动、被搜索命中、被另一个 AI 读到时，状态都在。而集中式索引必须靠人同步——本仓库已经证明它会掉队（`INDEX.md` 曾滞后 17 天，并遗漏了整整 26 份文件）。
