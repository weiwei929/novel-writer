# 项目开发日志

## 📅 2025年11月4日 - 重大技术突破

### 🎉 API路由架构修复成功

#### 问题背景
- **发现时间**：2025年11月4日凌晨
- **问题描述**：前后端API连接完全中断，所有请求返回404
- **影响范围**：整个应用的数据持久化功能无法使用

#### 解决过程
1. **问题定位** (01:30-02:30)
   - 通过浏览器开发者工具发现API请求失败
   - 分析服务器日志，发现路由匹配异常
   - 识别出Express.js路由配置问题

2. **根因分析** (02:30-03:00)
   - 发现 `app.use('/api', apiRouter)` 导致路径冲突
   - Express前缀匹配机制导致 `/api-test` 被错误路由
   - 路由顺序问题导致根路径处理器无法执行

3. **解决实施** (03:00-03:30)
   - 修改路由配置：`/api` → `/api/v1`
   - 重新启动服务器验证修复效果
   - 测试所有API端点确认正常工作

#### 技术细节
**修复前的问题配置：**
```typescript
app.use('/api', apiRouter)  // 匹配所有 /api* 路径
```

**修复后的正确配置：**
```typescript
app.use('/api/v1', apiRouter)  // 只匹配 /api/v1/* 路径
```

#### 验证结果
- ✅ 根路径 `/` 正常响应 200
- ✅ API测试页面 `/api-test` 可正常访问
- ✅ 所有 `/api/v1/*` 端点正常工作
- ✅ 服务器日志显示正确的路由执行

#### 影响评估
- **正面影响**：
  - 前后端数据流完全打通
  - API测试和调试能力恢复
  - 为后续功能开发奠定基础
- **风险控制**：
  - 向后兼容，无需修改现有API调用
  - 修改范围小，影响可控

## 📅 2025年12月11日 - 对齐思路，拉平进度与新武器 Mermaid

### 📝 主题概述
今日开发工作的核心围绕四个关键词展开：**对齐思路**、**拉平进度**、**校准颗粒度**，以及引入 **新的武器 Mermaid**。我们在完善现有功能的同时，着重提升了工程管理的精度和文档的可视化水平。

### 🔑 核心进展

#### 1. 对齐思路与校准颗粒度
- **看板系统完善**：完成了 Kanban 看板中已归档项目的"重开"（Return to Edit）功能，允许将完结项目恢复为草稿状态。这一改进对齐了用户对于项目生命周期管理的预期。
- **代码质量校准**：深入 `ProjectCard.tsx` 等组件，清理了未使用的变量和导入（如 `FileText` 的正确使用），解决了遗留的 Lint 警告。通过这种细颗粒度的代码清理，我们确保了代码库的健康度。
- **任务拆分优化**：将原本宏大的开发目标进一步拆解为可立即执行的微任务（如单一组件的 Bug 修复），有效提升了并行开发的效率。

#### 2. 引入新武器：Mermaid
- **可视化升级**：正式引入 Mermaid 作为技术文档和架构设计的核心工具。
- **应用场景**：利用 Mermaid 流程图和类图，我们能够更直观地展示业务逻辑（如项目状态流转）和系统架构。这不仅是文档工具的更新，更是团队协作语言的升级，帮助我们更快速地"拉平"对复杂逻辑的理解。

#### 3. 进度拉平与体验优化
- **UI/UX 细节**：在 Obsidian 模板优化任务中，我们统一了配色方案，并重新设计了扁平化风格的图标体系，确保了视觉体验的一致性。
- **各向同性**：无论是前端组件的交互细节，还是后端逻辑的文档描述，我们在各个维度上都保持了相同的推进步调，确保没有明显的短板阻碍整体交付。
