## 1. 整体架构呈现

### 1.1 应用类型

**单页应用 (SPA)** - React + React Router

- **前端**: React 18 + TypeScript + Vite
- **后端**: Fastify + Prisma + SQLite
- **通信**: RESTful API (`/api/v2/*`)
- **状态管理**: React Context + Zustand（部分）

### 1.2 页面路由结构

```
/ (首页)
├── /projects (项目管理 - 看板视图)
│   └── /projects/:id (项目详情)
├── /editor/:projectId/:chapterId (沉浸式编辑器)
├── /collections (文集管理)
├── /files (文件导入/导出)
├── /stats (数据统计)
├── /settings (系统设置)
└── /api-test (API 测试页面)
```

### 1.3 布局结构

**统一布局 (Layout)**:
```
┌─────────────────────────────────────┐
│  顶部导航栏 (Header)                 │
│  - Logo / 标题                      │
│  - 导航菜单 (首页/项目/文集/设置等) │
├─────────────────────────────────────┤
│                                     │
│  主内容区 (Content)                 │
│  - 根据路由动态加载页面组件         │
│                                     │
├─────────────────────────────────────┤
│  全局组件层                         │
│  - NotificationContainer (通知)     │
│  - LoadingOverlay (加载遮罩)        │
│  - ErrorBoundary (错误边界)         │
└─────────────────────────────────────┘
```

## 3. 底层逻辑架构

### 3.1 数据流

```
用户操作
  ↓
React 组件
  ↓
API 服务层 (frontend/src/services/api.ts)
  ↓
HTTP 请求 (Axios)
  ↓
Fastify 路由 (backend/src/routes/*)
  ↓
业务逻辑处理
  ↓
Prisma ORM
  ↓
SQLite 数据库
```

### 3.2 状态管理

**前端状态管理**:
1. **组件本地状态**: `useState` (大部分组件)
2. **全局 UI 状态**: Zustand Store (`uiStore.ts`)
   - 通知 (Notifications)
   - 加载状态 (Loading)
   - 主题 (Theme)
   - 侧边栏状态
3. **路由状态**: React Router (URL 参数)

**后端状态管理**:
- 无状态设计（RESTful API）
- 设置持久化: `SettingsManager` (JSON 文件)
- 数据库状态: Prisma + SQLite

### 3.3 API 交互模式

**统一响应格式**:
```typescript
// 成功响应
{
  success: true,
  data: { ... }
}

// 错误响应
{
  success: false,
  error: {
    code: 400,
    message: "错误信息"
  }
}
```

**请求拦截**:
- Axios 拦截器统一处理响应
- 自动解包 `data` 字段
- 统一错误处理

## 4. 用户操作流程

### 4.1 创建新项目流程

```
首页
  ↓
点击"开始创作"或进入"项目管理"
  ↓
点击"创建新项目"按钮
  ↓
填写项目信息（标题、作者、描述）
  ↓
选择文集（可选）
  ↓
创建成功 → 进入项目详情页
  ↓
创建章节 → 进入编辑器
```

### 4.2 导入外部作品流程

```
文件管理页面
  ↓
拖拽或选择 Markdown/TXT 文件
  ↓
预览解析结果
  ↓
确认导入
  ↓
后端验证格式（严格）
  ├─ 通过 → 创建项目和章节
  └─ 失败 → 显示详细错误信息
  ↓
AI 后台提取元数据
  ↓
显示元数据确认模态框
  ├─ 确认 → 保存为正式元数据
  └─ 拒绝 → 删除临时元数据
  ↓
导入完成 → 项目出现在"外部导入"列
```

### 4.3 写作流程

```
进入编辑器 (/editor/:projectId/:chapterId)
  ↓
编辑器自动加载章节内容
  ↓
开始写作（Markdown 格式）
  ↓
自动保存（2秒防抖）
  ↓
[可选] 使用 AI 助手
  ├─ 续写: AI 生成后续内容
  ├─ 改进: AI 优化当前文本
  └─ 头脑风暴: AI 提供创意建议
  ↓
[可选] 查看/编辑元数据
  ├─ 项目元数据（作品梗概、人物设定等）
  └─ 章节元数据（章节梗概等）
  ↓
保存并退出
  ↓
返回项目详情页
```

### 4.4 AI 审阅流程

```
项目详情页或看板视图
  ↓
点击"AI 审阅"按钮
  ↓
显示加载状态（AI 正在分析）
  ↓
显示审阅报告（Markdown 格式）
  ├─ 整体评分
  ├─ 逻辑问题列表
  ├─ 节奏分析
  └─ 改进建议
  ↓
用户阅读报告
  ↓
关闭模态框
```

## 5. 核心功能交互

### 5.1 编辑器交互

**快捷键**:
- `Ctrl/Cmd + S`: 手动保存
- `Ctrl/Cmd + P`: 切换预览模式
- `Ctrl/Cmd + F`: 查找（Monaco Editor 内置）

**自动保存**:
- 内容变化后 2 秒防抖
- 显示"保存中..."状态
- 保存成功后显示时间戳

**内容插入**:
- AI 建议 → 点击"接受" → 插入到光标位置
- 角色生成 → 插入到编辑器

### 5.2 AI 功能交互

#### AI 助手 (AIAssistant)

**触发方式**:
- 编辑器右下角浮动按钮（AI 模式下）
- 点击打开 AI 助手面板

**功能**:
1. **续写**: 基于当前内容，AI 生成后续 300 字
2. **改进**: AI 优化当前文本（文笔、节奏）
3. **头脑风暴**: AI 提供 3 个情节发展方向

**上下文注入**:
- Tier B 上下文（章节上下文）
- 包含项目元数据、章节梗概、前章摘要

#### AI 元数据助手 (AIMetadataAssistant)

**触发方式**: 元数据面板的"AI 辅助"按钮

**交互方式**:
- 对话式引导
- AI 提问 → 用户回答 → AI 生成内容
- 生成后可编辑
- 确认后保存到元数据字段

**重要提示**: 保存时会显示警告"此内容将成为 AI 写作和审阅的核心约束条件"

#### AI 全局审阅

**触发方式**: 项目卡片上的"AI 审阅"按钮

**工作流程**:
1. 收集所有章节内容
2. 构建 Tier C 上下文（全局上下文）
3. 调用 AI 生成审阅报告
4. 显示 Markdown 格式报告

### 5.3 元数据管理交互

**查看元数据**:
- 点击"项目元数据"或"章节元数据"按钮
- 显示字段列表
- 点击字段查看内容

**编辑元数据**:
- 点击"编辑此字段"
- 打开元数据编辑器
- 支持 Markdown 格式
- 保存后更新到数据库

**AI 辅助构建**:
- 点击"AI 辅助构建"按钮
- 打开 AI 元数据助手
- 对话式引导生成内容
- 生成后可编辑
- 确认保存

## 6. AI 功能集成方式

### 6.1 双层架构实现

**核心设计**: 手工创作层 + AI 辅助层（完全可选）

**实现方式**:
```typescript
// 检查 AI 是否启用
const aiEnabled = settingsManager.isAIEnabled()

// AI 组件条件渲染
if (!aiEnabled) {
  return null // 不渲染 AI 功能
}
```

**AI 功能入口**:
- 编辑器中的 AI 助手按钮（仅 AI 启用时显示）
- 元数据面板的 AI 辅助按钮（仅 AI 启用时显示）
- 项目卡片的 AI 审阅按钮（仅 AI 启用时显示）

### 6.2 上下文管理策略

**Tier A: 项目核心元数据（宪法级）**
- 作品梗概
- 人物设定
- 世界观
- 情节结构

**Tier B: 章节工作上下文**
- Tier A 内容
- 当前章节内容
- 章节梗概
- 前章摘要

**Tier C: 全局审阅上下文**
- Tier A 内容
- 所有章节摘要
- 整体结构分析

### 6.3 AI 服务抽象

**AIService 类**:
- 统一 AI 调用接口
- 支持多提供商（Gemini、OpenAI、Mock）
- 动态配置刷新
- 错误处理和降级

**PromptManager 类**:
- 构建系统提示词
- 注入上下文
- 管理不同场景的 Prompt

**ContextManager 类**:
- 构建 Tier A/B/C 上下文
- Token 管理（截断策略）
- 元数据提取和格式化

## 10. 总结：应用呈现特点

### 10.1 核心特点

1. **看板式项目管理**: 三列看板，直观展示项目状态
2. **沉浸式编辑器**: Monaco Editor，专业写作体验
3. **双层架构**: AI 功能完全可选，不影响手工创作
4. **元数据驱动**: 元数据作为"宪法"，指导 AI 生成
5. **严格导入验证**: 确保数据质量

### 10.2 用户体验亮点

- ✅ **直观的看板视图**: 一目了然的项目状态

- ✅ **灵活的元数据管理**: 支持 Markdown，AI 辅助构建
- ✅ **完善的导入流程**: 严格验证 + 元数据确认

### 10.3 技术实现亮点

- ✅ **类型安全**: TypeScript + Zod 验证
- ✅ **模块化设计**: 清晰的组件和服务分离
- ✅ **上下文管理**: 分层的 AI 上下文策略
- ✅ **错误处理**: 统一的错误响应格式
- ✅ **自动保存**: 防抖机制，避免频繁请求
