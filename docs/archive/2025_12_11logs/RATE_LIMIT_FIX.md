# 速率限制问题修复

**日期**: 2025年12月08日  
**问题**: 开发环境中速率限制过于严格，导致频繁触发限制

---

## 🔍 问题分析

### 问题现象
- 日志中频繁出现 "Rate limit exceeded" 警告
- 短时间内大量请求被限制
- 影响开发体验

### 根本原因
1. **速率限制配置过严**: 15分钟内100次请求对开发环境来说太严格
2. **未区分环境**: 开发和生产环境使用相同的限制
3. **重复请求**: 可能存在前端重复请求的问题

---

## ✅ 修复方案

### 1. 环境区分
- **开发环境**: 15分钟内 1000 次请求
- **生产环境**: 15分钟内 100 次请求
- **可选跳过**: 设置 `SKIP_RATE_LIMIT=true` 可完全跳过限制

### 2. 健康检查排除
- `/health` 和 `/status` 端点不限制

### 3. 认证限制优化
- **开发环境**: 15分钟内 50 次尝试
- **生产环境**: 15分钟内 5 次尝试

---

## 🔧 配置方法

### 方法一：使用环境变量跳过限制（推荐开发环境）

在 `backend/.env` 文件中添加：
```env
SKIP_RATE_LIMIT=true
```

或者在启动时设置：
```bash
SKIP_RATE_LIMIT=true npm run dev:backend
```

### 方法二：使用宽松限制（默认）

开发环境自动使用 1000 次/15分钟的限制，通常足够使用。

---

## 📊 限制配置对比

| 环境 | API 限制 | 认证限制 | 上传限制 |
|------|---------|---------|---------|
| 开发（默认） | 1000/15分钟 | 50/15分钟 | 10/小时 |
| 开发（跳过） | 无限制 | 无限制 | 10/小时 |
| 生产 | 100/15分钟 | 5/15分钟 | 10/小时 |

---

## 🚀 使用建议

### 开发环境
1. **推荐**: 设置 `SKIP_RATE_LIMIT=true` 完全跳过限制
2. **备选**: 使用默认的 1000 次限制（通常足够）

### 生产环境
- 使用默认的严格限制（100次/15分钟）
- 确保安全性

---

## ⚠️ 注意事项

1. **不要在生产环境设置 `SKIP_RATE_LIMIT=true`**
2. **开发环境跳过限制仅用于本地开发**
3. **如果仍有问题，检查是否有重复请求**

---

## 🔍 检查重复请求

如果仍然遇到速率限制问题，可能需要检查：

1. **前端是否有重复请求**
   - 检查 React 组件的 `useEffect` 依赖
   - 检查是否有多个组件同时请求相同数据

2. **自动保存频率**
   - 检查自动保存的触发频率
   - 考虑添加防抖（debounce）

---

## ✅ 验证

修复后，重启后端服务器，速率限制警告应该减少或消失。

```bash
# 重启后端
npm run dev:backend
```

---

**总结**: 已优化速率限制配置，开发环境使用更宽松的限制，并支持完全跳过。生产环境保持严格限制以确保安全性。
