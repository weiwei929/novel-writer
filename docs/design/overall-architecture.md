## 0. 设计前提：5 部门权力模型（Day 1 锁定，v4.1 修订）

整个系统只有**一个用户**（作者本人），但在不同阶段以不同身份参与。每个部门有明确的权力边界：

| 部门 | 状态范围 | 三选一节点 | 跨阶段退回？ |
|------|---------|-----------|------------|
| 创意组 | `creating` / `created` / `approved` / `shelved` | `created`（提案决策） | ❌ |
| 企划课 | `planning` / `planned` | `planning`（立项决策） | ❌ |
| 创作室 | `planned` / `writing` / `written` | `written`（提交审阅） | ❌ |
| 编审部 | `reviewing` / `reviewed` | `reviewed`（文集入库） | ❌ |
| 文集库 | `archived` | — | ❌ |

**v4.1 修订 — `shelved` 语义锁定**（Cursor 评审）：
- `shelved` = **主动暂存**（"我先放着，以后再写"）
- 提案通过企划课评估 = `approved`（**不**用 `shelved`）
- 退场到墓园 = 软删除（**不**改 status）

**v4.1 修订 — Chapter 状态锁**（Cursor 评审）：
- Chapter 仅有 `draft` / `writing` / `completed` 三值
- `written` 是 **Project 级别**状态（"全本所有 Chapter 都是 `completed`"）
- `writing` 是 **Project 级别**状态（"已有 Chapter 是 `writing`/`completed`"）

**关键不变量**：
- 三选一只发生在 4 个"本阶段最后环节"节点
- **跨阶段不退回**——部门 B 不能否决部门 A 的决定
- **退回到本阶段 in-progress**（如 `written → writing`），**不是退回到上阶段**
- 任何状态都可"删除"到**全局墓园**（`deletedAt` 软删除）
- 老板 = 作者本人；部门经理（创意组/企划课/创作室/编审部/文集库）都是作者的不同身份

**v4.1 修订 — 端点命名去歧义**（Cursor 评审）：
- `POST /proposals/:id/accept-into-planning` — 提案被企划课接受（→ `approved` + 创建 Project）
- `POST /projects/:id/confirm-greenlight` — 项目正式立项（→ `planned` + `greenlitAt=now`）
- 中文都用"立项"；API 名分开以免混淆

**7 个状态时间戳**（不变量）：

```
project.submittedToPlanningAt   // #1 提案被企划课接受
project.greenlitAt             // #2 正式立项
project.writingStartedAt       // #3 开始写作
project.workCompletedAt        // #4 作品已完成
project.submittedToReviewAt    // #5 提交审阅
project.archivedAt             // #6 文集入库
project.deletedAt              // 任何阶段可设的墓园标记
```

`greenlitAt IS NOT NULL` 是企划课 Tab ④"立项总账"的筛选条件。

**重投入阶段**（用户 Day 1 决定）：**创意组 + 创作室** 是重点打磨的阶段，其他阶段（企划课/编审部/文集库）相对流程化。

## 二、阶段间流转：4 个三选一节点

**重要修正（Day 1 锁定）**：原"四决策点"在每个阶段末尾都触发的设计被废弃。Day 1 锁定为**只在 4 个"本阶段最后环节"节点出现三选一**：

| 节点 | 阶段 | 状态 | 三选一按钮 |
|------|------|------|-----------|
| #1 | 创意组 | `created` | 提交企划课 / 退回（→ creating）/ 删除 |
| #2 | 企划课 | `planning` | 正式立项（confirm-greenlight）/ 退回（→ planning in-progress）/ 删除 |
| #3 | 创作室 | `written` | 提交审阅 / 退回（→ writing）/ 删除 |
| #4 | 编审部 | `reviewed` | 文集入库 / 退回（→ reviewing）/ 删除 |

**v4.1 修订 — 节点 #2 退回文案**（Cursor 评审）：
- "退回（→ planning）"是废文字（planning 既是阶段名也是状态名）
- 改为 **"退回（→ planning in-progress）"** 或更明确：**"退回本阶段设定中"**
- **Day 1 最小实现**（v4.1.1）：`Project.status` 仍为 `planning`，子阶段写在 `metadata._planningPhase`：
  - `evaluating` — 企划课评估中（节点 #1 通过后、正式立项前）
  - `setup` — 立项前完善中（Tab ③ 工作区）
  - `deferred` — 节点 #2 退回本阶段 in-progress（可配合 `metadata._rejectedAt`）
- **技术债（Day 1.1+）**：可升级为真字段 `planningPhase`，避免与 JSON 元数据混用

**"退回"语义重定义**：
- **跨阶段不退回**——创作室不能退回企划课的决定
- "退回"是本阶段决策的反悔：例如 `written` 退回 `writing`（"撤销完成"）
- 状态机端"退回"等价于"回到本阶段 in-progress 状态"

**删除的归宿**（Day 1 修订）：
- 任何状态下都可点"删除"
- 删除 = 软删除（`Project.deletedAt = now`）
- 落入**全局墓园**（不是某个阶段的回收站）
- 全局墓园是 L1 导航独立入口 🗑️，可恢复、可永久删除、可"留作遗迹"

**`planned` / `writing` 不是三选一节点**：
- `planned`（创作室 L1 待创作）：只有"开始写作"和"删除"二选一
- `writing`（创作室 L1 创作中）：只有"作品已完成"和"删除"二选一
- 这两个状态是"工作中"状态，不是"决定离开"状态

## 二点五、与原"四决策点"设计的差异

| 原设计 | Day 1 锁定 |
|--------|-----------|
| 每个阶段末尾都弹决策面板 | **只在 4 个节点**出现三选一 |
| 退回可跨阶段 | **跨阶段不退回** |
| 暂存审查池（全局搁置区） | **删除**用墓园替代，**无需审查池** |
| 删除 = 物理删除 | **删除 = 软删除**（`deletedAt`） |
| 恢复可"捞回任意阶段" | 墓园恢复保留原状态字段，**不预判后续流转** |

## 四、阶段 2：企划课

> 1. 4 Tab 调整为 [企划建议书] [立项评估] [作品设定中] [立项总账]


### 4.4 Tab ② — 立项评估（**三选一节点 #1**）

```
功能：对 Proposal 做三选一决策
AI参与：AI 审校官（评估辅助，默认关闭）
数据源：Proposal.status='created'

三种决策行为（Day 1 锁定，**v4.1 修订**）：
- 通过    → Proposal.status='approved'，创建 Project(status='planning', submittedToPlanningAt=now)  // API: `POST .../accept-into-planning`
- 退回    → Proposal.status='created'（**退回是反悔，不是删除；不退到上阶段**）
- 删除    → Proposal.deletedAt=now → 全局墓园（**不改** Proposal.status）

规则：
- 简化的三按钮，无复杂评估模板
- AI 审校官默认关闭
- 退回后创意组可继续编辑 Proposal 并重新提交
```

## 八、全局规则

> 本节于 2026-06-03 Day 1 重写。Day 1 关键变化：删除原"8.2 审查池"段，新增"8.2 全局墓园"。

### 8.1 阶段隔离（**强化 — Day 1 锁定**）

五个阶段互相隔离，**跨阶段不退回**（不变量）。字段随流程携带的规则：

```
创意组 → 企划课: 仅传递 Proposal（梗概+创新点+参考引用清单）
企划课 → 创作室: 仅传递 Project 立项作品（元数据+章节规划+greenlitAt）
创作室 → 编审部: 仅传递 全本正文（已完成章节 + submittedToReviewAt）
编审部 → 文集库: 仅传递 定稿作品（最终版 + archivedAt）
```

**字段随流程携带 — 不变量**：
- 一旦填入时间戳（如 `greenlitAt`），**只增不减**
- 7 个时间戳字段是"事件的不可变历史"
- 状态字段（`status`）可前可后，但时间戳记录"那一刻发生过什么"

**跨阶段不退回的实施**：
- 创作室 `written` 状态下的"撤销完成" = `written → writing`，**不回到企划课**
- 编审部 `reviewed` 状态下的"撤销定稿" = `reviewed → reviewing`，**不回到创作室**
- 如果觉得"上阶段做错了"，只能"上阶段重做"——回到上阶段的 in-progress 状态继续修，而不是把决定撤回

### 8.2 全局墓园（**取代审查池 — Day 1 关键变化**）

任何状态下都可点"删除"，落入**全局墓园**（`Project.deletedAt = now`）。

```
墓园规则（Day 1 锁定）：
- 墓园挂全局（不分阶段），🗑️ 入口在 L1 导航独立位置
- 软删除（deletedAt），非物理删除
- 字段名语义："曾经弄过这么个玩意"，带情感色彩
- 墓园中的作品可"恢复"（恢复后保留原 status，不预判后续）
- 墓园中的作品可"永久删除"（二次确认）
- 墓园可"留作遗迹"（看到就够了，不一定要恢复）
```

**为什么不用"审查池"**（Day 1 决定）：
- "审查池"暗示"待定"——而删除的情感是"放弃"
- 用户原话："带不喜欢的态度，能否救活看造化，更多体现曾经弄过这么个玩意"
- 字段名 `deletedAt` 配合"墓园"隐喻更自然
- 审查池的"可重新捞回原阶段"已被跨阶段不退回原则覆盖

**墓园 UI 草图**：

```
L1 导航：🗑️ 墓园（图标：墓碑或骨灰盒）

┌──────────────────────────────────────────────────┐
│  墓园                              清空 ▸        │
│                                                  │
│  民国悬疑：报社记者（已写作至第 5 章）            │
│    删除于 06-02  ·  最后状态：创作中              │
│    [查看遗物] [♻️ 恢复] [🗑️ 永久删除]             │
│                                                  │
│  都市言情：咖啡店（仅设定阶段）                  │
│    删除于 05-15  ·  最后状态：planning            │
│    [查看遗物] [♻️ 恢复] [🗑️ 永久删除]             │
└──────────────────────────────────────────────────┘
```

### 8.3 删除 = 软删除（`deletedAt`）

所有"删除"操作均为软删除，落入墓园。

```
软删除规则：
- Project.deletedAt = Date.now()
- 默认过滤：`WHERE deletedAt IS NULL`
- 恢复：`deletedAt = null`（保留其他字段不变）
- 永久删除：物理 DELETE，二次确认
```

**注意**：
- 删除是**三选一节点中的选项**（4 个节点都有删除按钮）
- 也可以是**状态内操作**（如"创作中"觉得不写了）
- 都是同一个墓园入口

### 8.4 灵感手记图库

- 图片仅存储在创意组内置小图库
- 不跟随项目流转
- 碎片本身不涉及图片上传时不阻塞操作

### 8.5 Collection 语义迁移

工程问题，内部处理。方案：原地重定义 Collection 为"文集"，现有数据兼容。

### 8.6 数据在全流程可精修

创作不是流水线——设定在创意组定义后，后面的阶段可以精修，不应锁死。

各阶段对作品设定的编辑权限：

| 数据 | 创意组 | 企划课 | 创作室 | 编审部 |
|------|--------|--------|--------|--------|
| 人物设定 | 创建 + 编辑 | 可编辑 | **可精修**（可选字段） | 可编辑（修正不一致） |
| 故事线 | 创建 + 编辑 | 可编辑 | **可编辑** | — |
| 创作心流 | 创建 + 编辑 | 只读参考 | 只读参考 | — |
| 作品内容元数据 | — | 创建（引用作品设定数据） | 只读 | 只读 |
| 写作风格 | — | 创建 + 编辑 | 只读 | 只读 |

**Day 1 变化**：
- 写作风格从元数据 JSON 提到顶层字段（`Project.writingStyle`），权限上"企划课创建 + 编辑"
- 创作室对写作风格只读，要改回企划课

**创作室的精修权限：** 允许临场新建人物、修改可选字段（经历/关系/口头禅）、增删故事线。核心字段（姓名/角色定位/性别）不建议在创作室改——如果真要改，那是大调整，应走阶段间回退。

**编审部的一致性检查：** 参照金庸连载经验——编审部 AI 审校官的一个重要职能是发现"第三章之后张三再也没出现过"这类连载遗留问题，而不是校对错别字。
