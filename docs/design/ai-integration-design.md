# AI 集成设计

> 2026-05-29 | 基于 5 阶段创作管道的 AI 布局方案
> 原则：用户为主 AI 辅、开关机制、关闭时人工链路不阻塞。

---

## 一、总则

### 三条硬约束

1. **用户为主，AI 为辅** — AI 永远是建议者，不是决策者。最终决定权在用户。
2. **AI 全局开关** — 每个阶段有独立的 AI 开关。关闭时，该阶段的人工工作流必须完整可用，不能有任何环节依赖 AI。
3. **不阻塞** — AI 操作（请求中/失败/超时）不得阻塞用户在该阶段的主线操作。AI 永远是"跑在旁边"的。

### 开关设计

```
系统设置 > AI 配置
┌─────────────────────────────────────────────┐
│  AI 功能总开关           [开启]              │
│                                             │
│  各阶段 AI:                                 │
│  ├─ AI 创意合伙人（创意组） [开启]  [⚙设置]   │
│  ├─ AI 审校官（企划课）    [关闭]            │
│  ├─ AI 写作助手（创作室）  [开启]  [⚙设置]   │
│  └─ AI 审校官（编审部）    [开启]  [⚙设置]   │
└─────────────────────────────────────────────┘
```

每个阶段开关独立。关闭后，该阶段所有 AI 入口隐藏或置灰。用户完全感觉不到 AI 的存在。

## 二、创意组 — AI 合伙人（大作用）

### 定位

AI 扮演"创意合伙人"角色：作者发起原始火种，AI 通过对话碰撞、联网调研、竞品分析、创新度评估帮助作者把火花炼成可用的策划方案。

### 功能清单

| 功能 | 交互模式 | 是否阻塞主线 | AI 开关粒度 |
|------|---------|------------|------------|
| 头脑风暴对话 | 聊天面板 | 不阻塞 | 创意组 AI 开关 |
| 联网素材调研 | 聊天内触发 | 不阻塞 | 同上 + 需联网权限 |
| 竞品对比分析 | 聊天内触发 | 不阻塞 | 同上 |
| 创意创新度评估 | 一键触发→出报告 | 不阻塞 | 同上 |

### 交互设计

```
创意组页面（当前 Scraps + 世界观 + 素材箱的统一入口）
┌────────────────────────────────────────────────────────┐
│  [创意组]                                  AI 开关 [on] │
│                                                       │
│  ┌──── 左侧面板 ────┐  ┌────  右侧 AI 面板（可收起）──┐│
│  │ 灵感碎片          │  │  AI 创意合伙人               ││
│  │ 素材箱            │  │  ┌─────────────────────────┐ ││
│  │ 世界观/角色/地点  │  │  │ 建议话题:               │ ││
│  │                  │  │  │  ○ 故事核心 brainstorm   │ ││
│  │                  │  │  │  ○ 角色关系碰撞         │ ││
│  │                  │  │  │  ○ 世界观设定推演       │ ││
│  │                  │  │  │  ○ 参考同类型作品       │ ││
│  │                  │  │  │  └─────────────────────────┘ ││
│  │                  │  │  │                              ││
│  │                  │  │  │  ┌─────────────────────────┐ ││
│  │                  │  │  │  │ [用户] 我想写一个民国  │ ││
│  │                  │  │  │  │ 背景的悬疑故事...      │ ││
│  │                  │  │  │  │ [AI] 好的，民国悬疑有 │ ││
│  │                  │  │  │  │ 几个经典方向...我们可以│ ││
│  │                  │  │  │  │ 先聊聊核心谜题的设计？│ ││
│  │                  │  │  │  └─────────────────────────┘ ││
│  │                  │  │  │  [输入框...]  [发送] [🔍搜索]││
│  └──────────────────┘  └────────────────────────────────┘│
│                                                       │
│  [保存为碎片] [创建角色] [创建地点] [转入企划课]        │
└────────────────────────────────────────────────────────┘
```

### 关键交互细节

- **头脑风暴对话**：类似 ChatGPT 的聊天界面，但每次对话可"归档"为碎片或直接创建角色/地点条目
- **联网搜索**：对话中用户点击 🔍 按钮，AI 自动搜索并返回摘要。搜索结果是建议性的，不会自动写入任何内容
- **竞品对比**：用户描述作品方向后，AI 列出同类作品并做差异化分析。结果以报告形式展示，可保存为参考笔记
- **创意评估**：一键触发，AI 从新颖度、完成度潜力、市场辨识度等维度给出评估。结果是对话中的一段建议，不是评分卡——避免"AI 打分"的压迫感

### 开关关闭时

右侧 AI 面板完全隐藏。用户仍然可以正常使用灵感碎片、素材箱、世界观管理的所有功能。不受任何影响。

## 三、企划课 — AI 校验（小作用）

### 定位

前期 AI 不参与。后期（作品大纲完成、章节结构搭好后）可做简单的检查性工作，辅助发现明显问题。

### 功能清单

| 功能 | 交互模式 | 是否阻塞主线 | AI 开关粒度 |
|------|---------|------------|------------|
| 章节结构均衡检查 | 一键→报告 | 不阻塞 | 企划课 AI 开关 |
| 作品元数据完整性检查 | 自动标记+一键修复 | 不阻塞 | 同上 |

### 交互设计

```
企划课页面（作品详情页 + 章节大纲）
┌────────────────────────────────────────────────────────┐
│  作品：未定名_1                     AI 校验 [off→on]    │
│                                                       │
│  ┌── 元数据面板 ──────────────────────────────────┐   │
│  │  名称：[____]  梗概：[____]  标签：[____]      │   │
│  │  状态：企划中                                   │   │
│  └──────────────────────────────────────────────────┘   │
│                                                        │
│  ┌── 章节大纲 ───────────────────────────────────────┐  │
│  │  □ 第一章 开端                       draft       │  │
│  │  □ 第二章 发展                       draft       │  │
│  │  □ 第三章 冲突                       draft       │  │
│  │  □ 第四章 高潮                       draft       │  │
│  │  □ 第五章 结局                       空          │  │
│  │                                                │  │
│  │  [AI 校验结果]（开关打开时显示）               │  │
│  │  ⚠ 第五章梗概为空                         │  │
│  │  ℹ 第一章字数偏短（120字，建议>300）        │  │
│  └──────────────────────────────────────────────────┘  │
│                                                        │
│  [新建章节] [导入章节] [转入创作室]                     │
└────────────────────────────────────────────────────────┘
```

### 关键交互细节

- 校验结果是非侵入式的——出现在页面底部，不会弹窗打断用户
- 每条校验结果用户可忽略（❌ 关闭），不影响操作
- "一键修复"只在用户确认后才执行

### 开关关闭时

校验区域不显示。企划课所有操作完全不受影响。

## 四、创作室 — AI 助手（中作用）

### 定位

写作过程中的辅助工具。有预设快捷入口（续写/润色/扩写），也可自由对话。所有输出由用户决定是否采纳。

### 功能清单

| 功能 | 交互模式 | 是否阻塞主线 | AI 开关粒度 |
|------|---------|------------|------------|
| 续写 | 选中文本→一键→出建议 | 不阻塞 | 创作室 AI 开关 |
| 润色 | 选中文本→一键→出建议 | 不阻塞 | 同上 |
| 扩写 | 选中文本→一键→出建议 | 不阻塞 | 同上 |
| 自由对话 | 侧栏聊天 | 不阻塞 | 同上 |

### 交互设计

```
编辑器（创作室）
┌─────────────────────────────────────────────────────────┐
│  【创作室】 作品：无题  章节：第一章            [≡]     │
│                                                        │
│  ┌── 编辑器 ─────────────────────┐  ┌── AI 助手 ─────┐ │
│  │                                │  │                │ │
│  │  这是一个漆黑的夜晚...         │  │  [续写] [润色] │ │
│  │                                │  │  [扩写] [自由] │ │
│  │                                │  │  ──────────── │ │
│  │                                │  │  [AI建议]     │ │
│  │                                │  │  夜风裹挟着海 │ │
│  │                                │  │  腥味扑面而来 │ │
│  │                                │  │  ...           │ │
│  │                                │  │  [采纳] [修改] │ │
│  │                                │  │                │ │
│  └────────────────────────────────┘  └────────────────┘ │
│                                                        │
│  右侧参考侧栏（角色/地点速查，与 AI 面板互斥切换）     │
└────────────────────────────────────────────────────────┘
```

### 关键交互细节

- **续写/润色/扩写**：用户选中文本后，点击对应按钮发送请求。AI 返回建议后，用户选择"采纳"（替换原文本）、"修改"（在对话中继续调整）或"忽略"
- **自由对话**：当前 AIAssistantPanel 已有，保留但增加预设按钮
- AI 建议不会自动写入编辑器，必须用户主动采纳

### 开关关闭时

AI 侧栏完全隐藏。右侧位置让给"参考侧栏"（角色/地点速查），写作不受任何影响。

## 五、编审部 — AI 审校（大作用）

### 定位

纯技术活，最适合 AI。全自动化处理文字校对、版式合规、前后逻辑错误、人物关系一致性检查。用户只需要确认结果。

### 功能清单

| 功能 | 交互模式 | 是否阻塞主线 | AI 开关粒度 |
|------|---------|------------|------------|
| 文字校对 | 一键→报告 | 不阻塞 | 编审部 AI 开关 |
| 版式合规检查 | 一键→报告 | 不阻塞 | 同上 |
| 前后逻辑检查 | 一键→报告 | 不阻塞 | 同上 |
| 人物关系一致性 | 一键→报告 | 不阻塞 | 同上 |
| 批量审校（全部） | 一键→综合报告 | 不阻塞 | 同上 |

### 交互设计

```
编审部（作品审阅工作台）
┌────────────────────────────────────────────────────────┐
│  [编审部]  作品：无题                         [全部审校]│
│                                                        │
│  ┌── 章节列表 ────┐  ┌── 审阅报告 ───────────────────┐│
│  │  □ 第一章   ✓  │  │  文字校对   版式   逻辑  人物  ││
│  │  □ 第二章   ⚠  │  │  ┌──────────────────────────┐ ││
│  │  □ 第三章   ✓  │  │  │ ● 人物关系:             │ ││
│  │  □ 第四章   ✗  │  │  │ 第2章"张三"第一次出现，│ ││
│  │  □ 第五章   ✗  │  │  │ 但第1章"老王"提到过    │ ││
│  │                │  │  │ "张三"，需确认是否同一人│ ││
│  │                │  │  ├──────────────────────────┤ ││
│  │                │  │  │ ● 文字校对:             │ ││
│  │                │  │  │ 第4章"突然"连续出现3次  │ ││
│  │                │  │  │ 第3章段落缩进不一致     │ ││
│  │                │  │  └──────────────────────────┘ ││
│  └────────────────┘  └────────────────────────────────┘│
│                                                        │
│  底部操作栏：[标记已处理] [批量忽略] [生成审阅报告]    │
└────────────────────────────────────────────────────────┘
```

### 审校报告结构

每条问题包含：
- 问题类型（文字/版式/逻辑/人物）
- 问题描述
- 原文位置（章节+段落引用）
- 修改建议
- 操作按钮：[跳转定位] [标记已处理] [忽略]

### 自动化程度

| 维度 | 处理方式 |
|------|---------|
| 文字校对（错别字/标点/语病） | 全自动扫描，标记所有疑点 |
| 版式合规（缩进/空行/段落长度） | 全自动扫描，标记不合规处 |
| 逻辑检查（时间线矛盾/情节漏洞） | 全自动扫描，输出疑点列表 |
| 人物一致性（名字统一/关系前后一致） | 全自动扫描，对比角色设定与正文 |

所有结果都是"建议"性质，用户逐条确认或批量忽略。不自动修改原文。

### 开关关闭时

审校功能入口隐藏。编审部的连续阅读、检查清单、修订快照等人工功能完全独立可用。

## 六、AI 开关架构

### 存储模型

```typescript
// 在 app-settings.json 中扩展
interface AISettings {
  enabled: boolean              // AI 总开关
  stages: {
    ideation: boolean           // 创意组 AI 开关
    planning: boolean           // 企划课 AI 开关（默认关闭）
    writing: boolean            // 创作室 AI 开关
    review: boolean             // 编审部 AI 开关
  }
  provider: 'deepseek' | 'openai' | 'ollama'  // 现有
  apiKey: string
  model: string
  // 创意组专用
  webSearch?: boolean           // 联网搜索权限
}
```

### 前端架构

```
components/ai/

│   ├── AIWebResearch.tsx       ← 联网调研（对话内触发）
```

```
前端全局 Context / Store
┌────────────────────────────┐

```

## 七、落地优先级

| 优先级 | 内容 | 理由 |
|--------|------|------|
| P0 | **创意组 AI 合伙人**（对话面板 + 预设话题） | 你明确说了"大作用"，且当前完全不存在 |
| P0 | **编审部 AI 审校**（校对/逻辑/一致性） | "大作用" + "纯技术活" + 当前只有实验性雏形 |
| P1 | **创作室 AI 增强**（续写/润色/扩写预设按钮） | 现有框架上增量，投入小见效快 |
| P1 | **AI 开关机制**（存储/前端架构/组件感知） | 所有 AI 功能的前置条件 |
| P2 | **创作室联网搜索**（创意组对话中的🔍） | 依赖 websearch 能力，可后置 |
| P3 | **企划课 AI 校验**（简单检查） | "小作用"，不着急 |

## 八、关键设计原则回顾

| 场景 | AI 表现 | 用户感受 |
|------|---------|---------|
| AI 返回结果 | 展示为建议，不自动写入 | "我看一下" |
| AI 请求中 | 不阻塞界面操作 | "让它跑着，我继续干" |
| AI 请求失败 | 显示错误提示，不影响功能 | "哦，下次再用" |
| AI 开关关闭 | AI 入口完全消失 | "这个功能本来就是纯手工的" |
| 网络不可用 | 所有 AI 功能优雅降级 | "联网功能暂不可用" |
