# 创作流程重构设计

> 2026-05-29 | 评估 + 设计建议
> 背景：用户提出以 5 阶段管道为核心的创作流程，要求评估现有架构完整性并借鉴同类工具。

---

## 一、5 阶段创作管道总览

```
创意组 → 企划课 → 创作室 → 编审部 → 文集库
   ↑___________| ← 允许反复
```

| 阶段 | 名称 | 职能 |
|------|------|------|
| 1 | **创意组** | 灵感碎片、素材导入、世界观管理（角色/地点/设定） |
| 2 | **企划课** | 将创意立项为项目，定作品大纲、章节结构、关联世界观元素 |
| 3 | **创作室** | 按章节在编辑器中创作，可随时查阅参考素材（不编辑） |
| 4 | **编审部** | 审稿、定稿、连续阅读、修订对比、检查清单 |
| 5 | **文集库** | 归档已完成作品，发布展示，统计 |

**核心原则**：各阶段是逻辑状态，不是硬隔离。项目在阶段间可前进、可回溯。无 AI 也能完整运作。

## 二、差距分析：现有架构 vs 5 阶段

### 阶段 1：创意组

| 需求 | 现有支持 | 差距 |
|------|---------|------|
| 灵感碎片收集 | `/scraps` 页面存在，CRUD 完整 | 碎片是全局的，没有和项目关联的构思空间 |
| 外部文件导入 | `/files` 页面存在，元数据提取有 | 导入后直接成项目，没有"作为素材暂存"的中间态 |
| 深度策划（角色/地点/世界观） | Character 和 Location 的数据库模型已存在 | **无后端路由、无管理界面**，完全不可用 |
| 构思成型 → 转入项目 | 无 | 缺乏从碎片/素材转化到正式项目的流程 |

**评分：2/10** — 数据层有基础，但从 UX 到 API 几乎全部缺失。

### 阶段 2：企划课

| 需求 | 现有支持 | 差距 |
|------|---------|------|
| 创建作品 | CreateProjectModal 可用 | ✅ |
| 作品详情页（名称/梗概/元数据） | ProjectDetailPage 可用，有 MetadataEditor | ✅ 但元数据编辑器和详情页分离 |
| 章节设定 | 章节 CRUD 在 ProjectDetailPage 内嵌 | 章节规划存在但无独立视图 |
| 章节梗概 | Chapter.metadata 可存梗概 | 章节列表不展示梗概，需点进编辑器才看到 |

**评分：6/10** — 基本功能可用但组织松散，缺少将构思正式"立项"的仪式感。

### 阶段 3：创作室

| 需求 | 现有支持 | 差距 |
|------|---------|------|
| 按章节创作 | EnhancedEditorPage 完整可用 | ✅ |
| 相关元素查看（不编辑） | **完全缺失** | 编辑器是全屏沉浸式，没有侧栏可以查阅角色/地点/设定 |
| 辅助创作（无 AI） | 无 | 没有写作目标、章节状态标记、草稿版本管理等无 AI 辅助功能 |
| 分屏参考 | 无 | Scrivener 的 split view、research panel 等缺失 |

**评分：4/10** — 编辑器核心功能不错，但缺少"创作环境"应有的上下文面板和辅助工具。

### 阶段 4：编审部

| 需求 | 现有支持 | 差距 |
|------|---------|------|
| 结构化审阅流程 | AIReviewPanel 存在 | 但没有非 AI 的审阅工作流 |
| 章节状态标记 | Chapter.status 仅有 "draft" | 没有 editing / reviewing / done 等状态 |
| 审阅清单/批注 | 无 | 缺少批注系统或 checklist |
| 修订对比 | 无 | 没有版本快照和 diff |

**评分：2/10** — AI 审查有，但结构化的人肉审阅流程几乎不存在。

### 阶段 5：文集库

| 需求 | 现有支持 | 差距 |
|------|---------|------|
| 存档已完成作品 | Project.status 有 "archived" | 但存档后缺乏"收入文集"的仪式感 |
| 文集管理 | Collections 页面存在 | 当前 Collections 被定位为"素材/设定"，和创作素材混淆 |
| 文集展示 | 无 | 没有文集封面、排序、简介等展示功能 |

**评分：4/10** — 概念存在但定位混乱，Collection 同时承担"世界观素材"和"文集"两个角色。

### 导航结构差距

```
当前导航（平铺 8 项）：
  首页 | 作品管理 | 素材/设定 | 灵感碎片 | 创作编辑 | 文件管理 | 统计 | 系统设置

按阶段组织的导航（最终命名）：
  创意组   → 企划课   → 创作室   → 编审部   → 文集库
  (阶段 1)    (阶段 2)    (阶段 3)    (阶段 4)    (阶段 5)
```

问题：
1. 平铺导航没有传达创作流程的递进感
2. "素材/设定"（Collections）命名歧义大——它到底是世界观素材还是已出版文集？
3. 编辑器是全屏模式隐藏导航，创作时需要参考其他模块只能跳出

## 三、同类工具调研与借鉴

### 3.1 Scrivener（行业标杆，桌面应用）

**核心概念**：Binder（层级项目树）+ Corkboard（虚拟索引卡）+ Outliner（数据表格）

| 可借鉴模块 | 说明 |
|-----------|------|
| **Binder** | 左侧层级树：作品/章节/场景/角色/地点/研究资料，拖拽排序 |
| **Corkboard** | 章节/场景以索引卡片展示，撰写梗概、颜色标记状态/POV |
| **Collections** | 虚拟分组——不改变实体位置，快速聚集相关片段 |
| **Snapshots** | 场景级版本快照，安全实验，随时回退 |
| **Scrivenings** | 连续模式——选择多个场景合并为连续文档审阅 |
| **Research Panel** | 分屏参考素材（图片/PDF/笔记），写作时并排查看 |

### 3.2 novelWriter（开源，跨平台）

**核心概念**：Markdown 原生 + @标签交叉引用系统

| 可借鉴模块 | 说明 |
|-----------|------|
| **@标签系统** | `@pov:Name` `@location:Name` `@char:Name`，场景与角色/地点自动交叉引用 |
| **项目树类型分色** | Chapter 蓝色、Scene 绿色、Character 紫色、Location 棕色 |
| **Outline View** | 表格化展示所有章节/场景，可自定义列（POV、地点、状态、字数） |
| **自动反向引用** | 角色文档中自动列出所有出现该角色的场景 |
| **Focus Mode** | 隐藏侧栏的全屏专注模式 |

### 3.3 StoryLine（Obsidian 插件）

**核心概念**：多视图场景管理 + 节拍表

| 可借鉴模块 | 说明 |
|-----------|------|
| **Board View** | 看板式场景卡片，按幕/章节/状态分组，拖拽排序 |
| **Plotgrid View** | 场景 × 情节线的矩阵视图，发现节奏漏洞 |
| **Timeline View** | 时间线视图，泳道分组（按角色/POV/地点） |
| **Plotlines View** | 追踪多条情节线在场景间的分布 |
| **节拍表模板** | Save the Cat、三幕剧、英雄之旅等预设结构 |

### 3.4 Plottr（付费，Web/桌面）

**核心概念**：Timeline 即一切

| 可借鉴模块 | 说明 |
|-----------|------|
| **Timeline 中心化** | 时间轴是核心视图，章节/场景/情节线都在时间轴上规划 |
| **情节线泳道** | 每一条情节线（主线/爱情线/悬疑线）作为独立泳道 |
| **场景卡片元数据** | 字数、POV、情感弧、状态、标签，全部在卡片上编辑 |

### 3.5 共性模式总结

| 模式 | 工具示例 | 核心价值 |
|------|---------|---------|
| 层级项目树（大纲） | Scrivener, novelWriter, Notion | 一目了然的结构，拖拽排序，快速导航 |
| 索引卡片 / 看板 | Scrivener Corkboard, StoryLine, Notion | 视觉化规划，直觉化操作 |
| 交叉引用 / 图谱 | novelWriter @tags, Obsidian | 角色/地点/场景自动关联，发现盲区 |
| 元数据列表面板 | novelWriter Outline, Plottr | 表格化管理，POV/状态/字数等一目了然 |
| 专注模式 + 参考面板 | Scrivener Split View, novelWriter Focus | 写作时不打断沉浸感，快速查阅资料 |
| 写作进度仪表盘 | Notion Templates, StoryLine Stats | 目标跟踪，持续激励 |

## 四、设计建议

### 4.1 导航重构：5 阶段主导航 + 系统工具

```
创意组             企划课             创作室             编审部             文集库
┌─────────┐       ┌─────────┐       ┌─────────┐       ┌─────────┐       ┌─────────┐
│ 灵感碎片 │       │ 作品管理 │       │ 编辑器   │       │ 审阅面板 │       │ 文集     │
│ 素材箱   │       │ 元数据   │       │ 参考面板 │       │ 批注     │       │ 归档     │
│ 世界观   │       │ 章节大纲 │       │ 写作辅助 │       │ 修订对比 │       │ 统计     │
│ 导入     │       │ 设定     │       │ 目标追踪 │       │ 检查清单 │       │         │
└─────────┘       └─────────┘       └─────────┘       └─────────┘       └─────────┘

系统设置（齿轮图标，右上角独立）
```

**核心变化**：
- 从平铺 8 项 → 按创作流程 5 阶段 + 1 系统
- 当前 Collections 分裂为"世界观素材"（归入创意组）和"文集"（归入文集库）
- 当前 Scraps 归入创意组，Files 归入创意组，Stats 归入文集库
- 编辑器不再隐藏导航——改为收窄导航以节省空间，但保留阶段切换能力

### 4.2 阶段 1「创意组」模块设计

```
创意组 (Ideation Desk)
├── 灵感碎片       ← 现有 Scraps 迁移，增加按项目关联
├── 素材箱          ← 新模块：导入的外部文件暂存，可标记"待改写"
├── 世界观          ← 新模块：角色管理 + 地点管理 + 自定义设定条目
│   ├── 角色卡片    ← Character 模型已存在，补 API + UI
│   ├── 地点百科    ← Location 模型已存在，补 API + UI
│   └── 设定集      ← 新自由形式条目（世界观规则、历史年表等）
├── 导入            ← 现有 FileManager 迁移
└── 转化按钮        ← "转为项目"：将碎片/素材打包为新项目
```

**关键设计决策**：
- 角色和地点不再是"AI 生成后不管"——它们是世界观管理的公民
- 素材箱是导入文件的中间状态，不强制立即形成项目
- 碎片可以标记关联项目，也可以独立存在

### 4.3 阶段 2「企划课」模块设计

```
企划课 (Planning Division)
├── 作品列表        ← 现有 ProjectsPage，只显示 draft/writing 状态
├── 作品详情页      ← 现有 ProjectDetailPage 增强
│   ├── 元数据面板  ← 名称、梗概、标签
│   ├── 章节大纲    ← 章节列表 + 梗概 + 排序（升级自现有 chapterPlanning）
│   ├── 设定关联    ← 从世界观中选择关联的角色/地点
│   └── 状态推进    ← draft → writing → reviewing → completed
└── 从构思导入      ← 选择碎片/素材/世界观条目，自动填充作品
```

**关键设计决策**：
- 章节规划从 Project.metadata.JSON 提升为独立 UI 模块
- 企划课只显示进行中的作品（不显示已归档的）
- 增加"从构思导入"的入口，连接阶段 1 → 阶段 2

### 4.4 阶段 3「创作室」模块设计

```
创作室 (Writing Studio)
├── 编辑器主体      ← 现有 EnhancedEditorPage
├── 参考侧栏        ← 新模块：右侧可收起的参考面板
│   ├── 角色速查    ← 当前项目关联的角色列表，点击展开详情
│   ├── 地点速查    ← 当前项目关联的地点列表
│   ├── 设定速查    ← 当前项目关联的设定条目
│   └── 本幕概要    ← 当前章节的梗概/要点（避免频繁切出）
├── 章节状态       ← 新：每个章节可标记 draft / revising / done
├── 写作目标       ← 新：本日/本章字数目标，进度条
└── 快速笔记       ← 新：写作中闪现的灵感，即时记录不打断沉浸感
```

**关键设计决策**：
- 参考侧栏默认收起，需要时展开——解决当前"编辑器全屏切断一切"的问题
- 参考侧栏只读（不编辑），定位上贯彻"创作时快速查阅"
- 写作目标/字数统计等无 AI 辅助，纯本地计算

### 4.5 阶段 4「编审部」模块设计

```
编审部 (Review Chamber)
├── 审阅清单        ← 新：自定义检查项（角色名一致/时间线合理/章节字数均衡等）
├── 连续阅读模式    ← 新：仿 Scrivener Scrivenings，将选定章节拼为连续文档阅读
├── 修订快照        ← 新：保存当前版本快照，修改后可对比
├── AI 审查         ← 现有 AIReviewPanel 保留（可选启动）
└── 状态推进        ← reviewing → completed，通知作品可存档
```

**关键设计决策**：
- 编审部是所有 reviewing 状态作品的集中工作台
- 无 AI 也能完成审阅——checklist + 连续阅读 + 修订对比是核心
- AI 审查作为可选增值，不是必经路径

### 4.6 阶段 5「文集库」模块设计

```
文集库 (Library)
├── 文集             ← 新：汇集已完成作品，支持封面/简介/排序
├── 归档作品         ← Project.status = completed 自动流入
├── 统计仪表盘       ← 现有 StatsPage 迁移
└── 导出             ← 新：导出为 EPUB / PDF / DOCX
```

**关键设计决策**：
- 文集库是已完工作品的展示厅，与"世界观素材"彻底分离
- Collection 模型保留，但语义变为"文集"——一个文集包含多部作品
- 统计仪表盘放在这里合理——在完成创作后看全局数据

### 4.7 推荐优先级路线

```
Phase 1（最优先 — 补核心断层）
├── 世界观管理（角色 + 地点 API + UI）← 数据模型已有，API 和 UI 缺失
├── 参考侧栏（编辑器内查看角色/地点/设定）
└── 导航重构（5 阶段结构 + Collections 语义拆分）

Phase 2（增强体验）
├── 章节大纲独立视图（从 metadata JSON 中提升）
├── 素材箱（导入中间态）
├── 写作目标/字数追踪
└── 章节状态扩展（draft → revising → done）

Phase 3（审阅与存档）
├── 审阅清单 + 连续阅读模式
├── 修订快照
├── 文集库
└── 导出功能
```

## 五、潜在风险与注意事项

1. **Collections 语义变更**：现有数据中 Collection 可能已存储"世界观素材"，迁移时需考虑数据兼容
2. **导航重构影响面大**：App.tsx、Layout.tsx、所有页面路由均需调整，建议分步实施
3. **编辑器参考侧栏**：当前编辑器是全屏 Monaco，添加侧栏需要重新设计布局
4. **SQLite 写并发**：SQLite 在审阅/批注等高频写入场景需注意锁竞争
5. **GitHub 访问**：VPS 在深圳，未来代码同步策略需要提前确定（备选：gitee 镜像 / 直接 scp）
