## 2026-07-07 会诊后更正（置顶摘要）

本文档 §0-§6 描述的原始方案——"快速开始写作 = 只填作品名称 → 自动建 Project + 第一章 → 直接进 `writing` 路由"——已在实现（`994f08a`）与后续会诊侦察中被证伪：新建 `Project` 落库为 Prisma 默认原始状态 `draft`，但 API 读路径统一经 `status-migration.ts` 的 `PROJECT_STATUS_MAP` 映射为 `planning`，`getWorkPermissions('planning').body === false`，写作页据此把新建作品重定向到 `/work/:id`，而非停留在写作页。这是设计假设失效，不是实现 bug（详见会诊侦察回报）。

会诊裁决后，HomePage 快速入口的唯一合法语义收束为：

> **继续写作：直接恢复最近更新的创作中（`status=writing`）作品与其最近更新的章节；不产生任何新内容对象（不新建 Project、不新建 Chapter）。**
>
> 若不存在合法的 `writing` 作品：**进入现有创作室列表（`/writing/projects`），提示"暂无创作中作品"，流程结束。**

以下内容**不属于**当前范围，不在本卡或其后续卡中实现：

- 灵感碎片相关能力（详见 2026-07-07《Cursor 会诊侦察卡：novel-writer 快速表达入口》回报）
- "先写后分流"快速表达输入窗口
- HomePage 双入口（"继续写作" + "新建作品"并列）——当前只保留"继续写作"一个入口，新建作品维持走原有普通创建路径（未接入 HomePage）

`WritingEditorPage` 的以下两项成果与上述被证伪的创建假设**无关**，是独立的写作页可靠性/交互修复，继续保留并生效：

- 章节导航默认收起为抽屉，顶栏「目录」按钮独立展开/收起（不依赖任何"新建即直达"假设，对所有已存在的写作页作品同样适用）
- 保存失败态（`saveError`）与页面级致命错误解耦：保存失败时编辑器与正文继续保留在页面上，用户可点击重试，不会被整页错误替换（这是本文档 §2 状态 E 与 §6 第 3 项工程差距点名的业务不变量落实，与入口语义无关）

对应实现：`feature/quick-writing-loop` 分支，撤回 `CreateProjectModal.tsx` 的 `variant="quick"` 接线（外科式撤回，未做整 commit revert），`HomePage.tsx` 改为调用只读的"继续写作"恢复逻辑。验证证据见 `frontend/scripts/quick-writing-loop-smoke.mjs`（继续写作专项）与 `frontend/scripts/quick-writing-loop-smoke-task23.mjs`（章节抽屉 + 保存可靠性回归）。

## 0. 本轮要解决什么

现状（已核实）：完整的「创意 → 企划 → 章节规划 → 开始创作」链路已贯通，但**应用内没有任何可点击的「新建作品」入口**——唯一具备该逻辑的组件 `CreateProjectModal.tsx` 从未被引用。用户若想跳过企划、直接写一章，无路可走。

本轮设计目标：在**保留完整企划链**的前提下，增加一条并列的「快速开始写作」路径：

```text
点「快速开始写作」→ 只填作品名称 → 系统自动建「第一章」→ 直接进入写作页
```

两条路径共用同一套 `Project` / `Chapter` 模型、同一个写作页路由，不新增任何字段、状态或页面骨架。

## 2. 关键视觉状态

### 状态 A — 快速入口所在页面：HomePage

**位置**：`HomePage.tsx` 顶部 `<header>` 区域，标题右侧新增一个强调按钮，与「五阶段卡片」区之间形成视觉呼应但不混入卡片网格（卡片网格是**导航**，这个按钮是**动作**，语义不同不应同构）。

```text
┌─────────────────────────────────────────────────────────────┐
│  我的小说创作工作台                      [✎ 快速开始写作 →]   │
│  五阶段创作流程一览                                            │
├─────────────────────────────────────────────────────────────┤
│  [创意组] [企划课] [创作室] [编审部] [文集库]   ← 现有五卡片   │
└─────────────────────────────────────────────────────────────┘
```

**视觉规格**：

- 按钮色：`bg-indigo-600 hover:bg-indigo-700 text-white`（对齐 `Layout.tsx` 写作 tab 的 `tabActive: bg-indigo-600`，让用户下意识把这个动作和"创作室"域关联）
- 图标：复用既有 `IconPenTool`（已用于 `KanbanBoard.tsx` 草稿列）
- 尺寸与「查看更多」链接同级字号，但用实心按钮而非文字链接，强调"这是一个动作，不是导航"
- 移动端（`sm:` 以下）：按钮换行到标题下方，全宽，不与标题挤压

**为什么这样放**：HomePage 是所有用户的默认落地页；五阶段卡片区已经是「浏览/导航」语义，新增一个「创建」语义的按钮如果塞进卡片网格会造成误读（用户可能以为它也是一个"阶段入口"）。放在 header 区域，与标题同级，明确传达"这是全局动作"。

### 状态 B — 最小创建表单

**触发**：点击「快速开始写作」→ 弹出居中模态框（复用 `CreateProjectModal.tsx` 的容器样式：`fixed inset-0 bg-black/50` + `bg-white rounded-lg`），但内容大幅精简。

```text
┌───────────────────────────────────────┐
│  开始一部新作品                    ✕   │
├───────────────────────────────────────┤
│                                         │
│  作品名称 *                            │
│  ┌───────────────────────────────────┐ │
│  │ 输入作品名称                        │ │
│  └───────────────────────────────────┘ │
│                                         │
│  创建后将自动生成「第 1 章」，           │
│  直接进入写作页。                       │
│                                         │
│         [取消]      [开始写作 →]        │
└───────────────────────────────────────┘
```

**与现有 `CreateProjectModal` 的差异**（视觉 + 字段层面，非新组件体系）：

| 项 | 现有 `CreateProjectModal` | 快速创建 |
|----|---------------------------|----------|
| 必填字段 | 标题 + 作者 + 梗概 | **仅标题** |
| 状态选择 | 手动下拉（草稿/企划中/创作中/已完成） | 无 UI，固定 `draft`（复用现有默认值，非新状态） |
| 标签、描述 | 有 | 无 |
| 「自动生成第 1 章」开关 | 可关闭 | **固定开启，不可关**（业务已批准第 4 条） |
| 提交按钮文案 | "创建" | "开始写作 →"（传达"点完就能写"的预期） |
| 提交后跳转 | `/work/:id`（作品详情） | **直接进 `/writing/:id/:chapterId`**（见状态 C） |

**空状态 / 校验**：标题为空时按钮 disabled（复用 `CreateProjectModal` 现有 `!formData.title.trim()` 逻辑的视觉表达：置灰 + `cursor-not-allowed`），不新增校验规则。

### 状态 C — 第一章写作页：默认纯净态

**路由**：`/writing/:projectId/:chapterId?from=writing`（与 616 主链完全一致的路由，不新增路由）

```text
┌──────────────────────────────────────────────────────────────┐
│ ←返回   《我的新书》 › 第 1 章 · 未命名章节 ⌄        [● 已保存] │ ← 顶栏
├──────────────────────────────────────────────────────────────┤
│                                                                │
│                                                                │
│               （空白 Markdown 编辑区，光标聚焦）                │
│                                                                │
│                                                                │
└──────────────────────────────────────────────────────────────┘
```

**与现状的关键差异**：左侧 `ProjectNavigationPanel`（章节列表栏）**默认不渲染**，编辑区占满可用宽度。

**"纯净但不迷路"的实现方式**（继承顶栏已有元素，仅做可交互升级）：

- 顶栏标题区把原本静态的 `《书名》` 与 `第 X 章 · 标题` 合并为一条**面包屑**，中间加 `›` 分隔符
- 面包屑末尾加一个小号 `⌄`（复用 `IconArrowDown`，18px），点击后展开章节导航（状态 D）
- 这条面包屑本身就是"章节位置感"——不需要额外的进度条或页码组件，因为顶栏这个位置在现有代码里已经存在（`WritingEditorPage.tsx` L358-372），只是从纯展示文字升级为可点击

**不做的事**：不引入悬浮侧边小圆点导航、不做迷你缩略图大纲——这类新组件会打破"纯净"目标，也超出"继承现有成果"的边界。

### 状态 D — 章节导航展开态

**触发**：点击顶栏面包屑末尾 `⌄`，或点击工具栏新增的「目录」按钮（见下）。

```text
┌───────┬──────────────────────────────────────────────────────┐
│ 目录  │ ←返回  《我的新书》 › 第 1 章 · 未命名章节 ⌃  [●已保存]│
│───────┼──────────────────────────────────────────────────────┤
│ 第1章 │                                                        │
│ ▍未命名│              （编辑区，宽度收窄）                       │
│       │                                                        │
│ + 新增 │                                                        │
│  章节  │                                                        │
└───────┴──────────────────────────────────────────────────────┘
```

**规格**：

- 展开的面板**不是**现有 `ProjectNavigationPanel`（那个含"作品梗概/元数据设置"等企划信息，对快速写作场景过重）；而是它的**精简子集**：仅标题、章节列表、"新增章节"入口
- 交互上是**临时展开的抽屉**（点击外部或再点 `⌃` 收起），不是持久布局分栏——这样"默认纯净"和"需要时能看全局"两个诉求都满足，且不需要为"是否记住展开状态"这类偏好新增持久化逻辑
- 工具栏侧新增「目录」按钮，纳入现有 `ModeButton` 分段控件组（写作 / 参考 / AI / 审阅 → **目录 / 写作 / 参考 / AI / 审阅**），复用同一套选中态样式，不新增按钮风格

---

### 状态 E — 保存状态：安静但可信

沿用现有三个 state（`saving` / `hasUnsavedChanges` / `lastSaved`），**只重设计视觉，不改变触发逻辑**（触发逻辑属工程范畴，不在本卡范围）：

```text
写作中（有未保存改动）     ●  编辑中…            （灰点 + 灰字，安静，不打扰）
保存中                    ◐  正在保存…            （旋转小图标，短暂出现）
已保存                    ✓  已保存 · 14:32       （绿色小勾，随后 2 秒后淡化为纯时间戳）
保存失败（新增，见 §6）    ⚠  保存失败 · 点击重试   （琥珀色，常驻直到重试成功，不自动消失）
```

**位置**：仍在顶栏标题区右侧（继承现状位置，不新增独立状态栏），但从纯文字（`● 未保存` / 时间戳）升级为「图标 + 文字」的统一视觉语言，四态共用一个插槽，避免布局跳动。

**"不能静默丢稿"的视觉落实**：新增「保存失败」态为**唯一的常驻警示态**——不随时间淡化、不允许静默消失，必须用户点击"重试"或手动保存成功才能清除。这是本设计对业务不变量（已批准第 9 条）的视觉承诺；**实际的失败检测与重试机制是工程实现**，见 §6 工程差距第 3 项。

## 4. 需要 Commander 决定的取舍（最多 3 项）

### 决定 1：快速入口放在 HomePage 还是创作室列表页（`WritingProjectsPage`）？

- **Cursor 推荐：HomePage**。理由：HomePage 是所有会话的默认落地页，触达面最大；`WritingProjectsPage` 只有已经点进"创作室"的用户才会看到，对"完全新用户想跳过企划直接写"的场景反而更晚被发现。

### 决定 2：章节导航的展开触发——点击顶栏面包屑文字，还是新增独立的「目录」按钮？

- **Cursor 推荐：两者都做，但以「目录」按钮为主入口**。理由：面包屑本身承担"位置感"信息职责，若同时作为唯一交互入口，容易被误认成"面包屑导航"（点了会跳转）而非"展开列表"；独立按钮更符合现有 `ModeButton` 分段控件的既有心智模型，面包屑上的 `⌄` 作为次要的视觉提示保留即可。

### 决定 3：保存失败态的呈现强度——顶栏小图标 + 文字（如方案），还是升级为页面顶部整条醒目横幅？

- **Cursor 推荐：维持顶栏小图标 + 文字**，但**保存失败时按钮从灰色变为琥珀色描边，且常驻不消失**。理由：整条横幅会打破"安静"目标，且这是低频事件（正常网络下很少发生）；用颜色 + 持久性而非面积来传达"重要但不吵"。

## 6. 给 Codex：工程差距与实施建议

### 设计文档路径

`docs/design/quick-writing-entry-2026-07-07.md`（本文件）

### 复用的现有设计成果

- `CreateProjectModal.tsx` 创建 + 自动建章逻辑（L38-66）
- `WritingEditorPage.tsx` 顶栏结构、三个保存 state、`ModeButton` 分段控件
- Design Mode 配色体系（`9b07129`）
- 路由 `/writing/:projectId/:chapterId`、权限函数 `getWorkPermissions`

### 覆盖的页面与状态

`HomePage`（新 CTA）→ 快速创建模态（新，轻量）→ `WritingEditorPage`（默认纯净 + 面包屑可展开 + 目录抽屉 + 保存四态）。

### 与当前实现的工程差距（供后续任务卡拆分，本卡不实现）

1. **入口接线**：`HomePage.tsx` 新增按钮 + 快速创建模态组件（可基于 `CreateProjectModal.tsx` 裁剪，而非从零写）。
2. **创建后跳转目标变更**：现有 `CreateProjectModal` 提交后 `navigate('/work/:id')`；快速创建需要拿到自动创建的第 1 章 `id` 后 `navigate('/writing/:id/:chapterId?from=writing')`。**关键发现**：`draft` 状态在 `getWorkPermissions()` 中返回 `FULL` 权限（`workPermissions.ts` L28-29），`WritingEditorPage.loadData` 只检查 `permissions.body`（L151-154），因此**新建作品无需先过 `start-writing` 状态流转**即可直接打开写作页——这大幅降低了本项工程量，无需碰 616 状态机。
3. **保存失败可见化（业务不变量，非可选）**：当前 `MarkdownEditor.tsx` L119-120 自动保存失败时仅 `console.error`，用户无感知。需要：(a) 捕获 `onSave` 抛出的异常并回传可见状态；(b) 新增"重试"动作（可直接复用 `handleSave` 现有函数，无需新 API）。**这是本卡发现的唯一与"不能静默丢稿"直接相关的现状缺口，建议列为下一实施任务卡的 P0 项**。
4. **`WritingEditorPage` 左栏默认隐藏 + 抽屉化**：需要新增一个精简版章节列表组件（区别于承载企划信息的 `ProjectNavigationPanel`），或给现有组件加一个"精简模式" prop——具体技术选型（新组件 vs prop 开关）留给实施任务卡判断，不在本设计卡决定。
5. **顶栏面包屑可交互化**：`WritingEditorPage.tsx` L358-372 现有纯文字节点改为按钮，绑定展开状态——改动面很小（同一文件内新增一个 `useState` + `onClick`）。

### 建议实施顺序

1. 保存失败可见化（P0，独立于其他改动，风险最低，直接兑现业务不变量）
2. 快速创建入口 + 跳转目标修正（复用现有 Modal 逻辑，改动集中在 1-2 个文件）
3. 写作页默认纯净 + 面包屑可展开（改动集中在 `WritingEditorPage.tsx`）
4. 精简章节抽屉组件（工作量最大，可放最后）
