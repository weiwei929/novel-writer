## 1. 616-B 定位

### 1.1 616-B 只定义

```text
作品设定最小模型
```

回答一个问题：

> **这部作品如何成立？作者写作与企划交接时，需要遵守和回看的创作指南是什么？**

### 1.2 616-B 不定义

| 不属于 616-B | 归属 |
|--------------|------|
| 作品章节模型（顺序、标题、梗概、状态） | **616-C** |
| 创意组机制（缘起、构思、来源池） | **creative-v2** 已裁决 |
| WorldBuilding / Character / Timeline 是否重启 | 616 宪法 §3：**冻结**；本文不重启 |
| 旧六字段最终迁移脚本与 canonical 写入键 | **616-B-A 及以后实现卡** |
| AI prompt 最终结构与适配层 | 616 宪法 §6 + 后续专项 |
| 正文、编审、文集呈现 | 616 宪法 §2.4 / §4 |

### 1.3 与 616-A 的关系

616-A 已完成：

- 产品命名「作品设定」、遗留资料只读
- 梗概读模型 `getWorkSynopsis` 与立项双写

616-B **不重复** A 的命名与梗概工作，**落实** A 刻意留空的「作品设定内部结构」——但仅到**最小模型**层级，不落地 UI 与存储。

## 2. 作品设定身份

写入裁决：

```text
作品设定首先是作者写作时回看的指南，
同时是企划课与创作室之间的内容契约；
AI 只能作为参考上下文消费者，不能反向决定结构。
```

展开说明：

| 维度 | 含义 |
|------|------|
| **作者指南** | 写作过程中可随时打开、修改；以可读散文/要点为主，不是填表任务 |
| **内容契约** | 企划课完善后的设定，是创作室右侧「设定参考」的权威来源；创作室可调整，但应保留生长痕迹 |
| **AI 角色** | 系统适配层可从描述式设定组装 prompt；**禁止** AI 字段清单反向塑造作者心智 |

作品设定**不是**：

- raw JSON 暴露给作者
- 旧六字段表单复活
- 「世界观 / 世界规则 / 约束 / 设定集」等压迫性产品语言
- 创意组的「讨论评估」或外来参考的「材料绑定」

## 3. 连续生长原则

连续生长原则已作为 **616 内容资产宪法** §2 补充原则；本文仅在作品设定专项中展开其对企划课的影响。

### 3.1 总原则

```text
每个阶段承接上一阶段已成立的内容，原则上不轻易改写；
再生长本阶段最重要的内容资产。
```

五阶段不是割裂工位，而是**同一部作品生命的不同阶段**。后一阶段默认信任前一阶段的交付，在其上**补全、加深**，而非推倒重来。

**不轻易改写的含义：**

- 标题、梗概等作品身份级信息：进入企划课后原则上不在主流程内推翻（616 §5）
- 已写定的设定块：创作室可修订，但属于「生长」而非「换一部作品」
- 若种子不再成立 → **作品暂存**或重新立项，而非静默覆盖

### 3.2 五阶段承接与生长

```mermaid
flowchart LR
  C0[创意缘起] --> C1[创意作品雏形]
  C1 --> P1[作品设定 + 章节]
  P1 --> W1[正文]
  W1 --> R1[审阅意见]
  R1 --> L1[归档呈现]
```

| 阶段 | 承接 | 本阶段生长 |
|------|------|------------|
| **创意组** | 创意缘起（可选） | **创意作品雏形**：标题 + 梗概（必填）；作品预期、设定雏形（可选） |
| **企划课** | 创意作品雏形 | **作品设定**（三必一选完善）+ **作品章节**（616-C） |
| **创作室** | 设定 + 章节结构 | **作品正文**（章节为写作单位） |
| **编审部** | 正文 + 设定 + 章节 | **审阅意见**（只读对照设定，不直接改设定） |
| **文集库** | 审阅后作品 | **归档与呈现**（正文为主体） |

## 4. 作品设定最小模型：三必一选

### 4.1 结构

```text
人物与关系      ← 必
时间与地点      ← 必
事件与情节      ← 必
叙事风格 / 创作心流  ← 选
```

### 4.2 形态原则

| 原则 | 说明 |
|------|------|
| **描述式，不表单式** | 每块是一块**创作设定文档**（自由文本为主），不是姓名/性格/地点/规则的细碎字段表 |
| **不拆机器字段** | 不在产品层暴露「人物姓名」「性格」「地点」「规则」等子字段；底层存储可结构化，作者不见 |
| **语言去压迫** | 不使用「世界观」「世界规则」「约束」「设定集」等旧式或压迫性标签；用作者自然的四块名称 |
| **可空起步、逐步写满** | 创意组可只写一块雏形；企划课完善为完整设定 |

### 4.3 各块回答什么

| 块 | 作者自问 | 典型内容（描述式） |
|----|----------|-------------------|
| **人物与关系** | 谁在场？彼此什么关系？ | 主要人物、关系张力、对手与盟友 |
| **时间与地点** | 故事何时何地展开？ | 时代、季节、主场景、氛围 |
| **事件与情节** | 发生什么？如何推进？ | 主线、关键转折、结局走向（可粗可细） |
| **叙事风格 / 创作心流**（可选） | 怎么讲？什么腔调？ | 视角、文风、节奏、参考气质 |

第四块合并原「创作心流」与叙事风格类意图，**可选**；缺省不阻断企划向创作室交接（见 §6 验收草案）。

### 4.4 与旧六字段的关系（产品层）

旧 `characters` / `timeline` / `settings` / `relationships` / `plotStructure` 等**不复活**为新产品结构。其语义**大致映射**到新四块，但：

- 不做 1:1 字段迁移承诺
- 旧数据只读兼容
- 新模型不采用旧表单布局

| 旧字段（legacy） | 新块（语义参考，非迁移键） |
|------------------|---------------------------|
| `characters` + `relationships` | 人物与关系 |
| `timeline` + `settings`（背景设定） | 时间与地点 |
| `plotStructure` | 事件与情节 |
| CreativeFlow / 叙事类残留 | 叙事风格 / 创作心流（可选） |

## 5. 创意组与企划课衔接

### 5.1 创意组阶段（承接 creative-v2）

创意组交付的是**创意作品雏形**，不是完整作品设定。

```text
标题 + 梗概          ← 必填（提交企划课硬门槛，creative-v2 已裁）
作品预期             ← 可选（企划接收前补强，_workExpectation）
设定雏形（可选）     ← 四块均可选填，有则带入企划课
  · 人物与关系
  · 时间与地点
  · 事件与情节
  · 叙事风格 / 创作心流
```

- 创意组**可以**提前写设定雏形，**不得**要求写满三必一选
- 设定雏形是「种子上的嫩芽」，不是企划课表单的前置必填

### 5.2 企划课阶段

企划课**不是从空白表单开始**。

```text
承接：创意作品雏形（标题、梗概、作品预期、设定雏形若有）
生长：把设定雏形完善为作品设定（三必一选）
并行：构建作品章节（616-C）
```

产品叙事：

> 作者带来的构思与零星设定，在企划课被**接过来、写清楚**；企划课编辑的是**同一件作品的生长**，不是另起炉灶。

### 5.3 交接契约（草案）

创意组 → 企划课（待企划作品接收）至少交接：

| 项 | 必填 |
|----|------|
| 标题 | 是 |
| 梗概 | 是 |
| 作品预期 | 企划接收前补强（creative-v2） |
| 设定雏形 | 否（有则继承） |
| 构思备注 | 否（`_creativeNotes`，过程痕迹） |

企划课 → 创作室（confirm-greenlight / 提交创作室）见 §6。

## 6. 企划中阶段

企划中（`Project.status = planning`，企划课工作区）须完成两件事：

```text
作品设定
作品章节
```

二者同属企划中，但**不是同一个模型**（设定见 616-B，章节见 616-C）。

### 6.1 默认引导顺序

```text
先设定基底，再章节构建；
但允许二者来回调整。
```

- 默认 UX 引导：作者先补「三必」，再建章节列表
- **不强制线性**：可先列章节提纲再回头补人物；系统用缺项提示而非锁死流程

### 6.2 提交创作室前 · 最低验收（草案）

以下为**产品验收草案**，是否全部作为硬门槛见 §9 未决问题。

```text
作品设定前三项有内容（人物与关系、时间与地点、事件与情节）
至少有一个章节
每个章节至少有：标题 + 章节梗概
叙事风格 / 创作心流：可选
```

说明：

- 「有内容」= 非空描述文本，不设最低字数机器规则（实现时可做极弱校验）
- 章节细则（顺序、状态、与正文章节关系）归 **616-C**

### 6.3 与外来参考 legacy 拆章

creative-v2 agenda 第三组：complete → 自动拆章为 **legacy**，未来归 616-C / 企划课显式动作。

616-B **不包含**「从 FileReference 生成章节」；仅保证设定模型独立。

## 7. 与 616-C 边界

| | **616-B** | **616-C** |
|---|-----------|-----------|
| **对象** | 作品设定 | 作品章节 |
| **模型** | 三必一选（描述式四块） | 章节顺序、章节标题、章节梗概、章节状态 |
| **阶段** | 企划中生长；创作室可读可调整 | 企划中搭建；创作室按章写作 |
| **创意组** | 仅可选「设定雏形」 | 不涉及 |
| **验收** | 前三项有内容 | 至少一章且每章有标题+梗概 |

```text
616-B：作品设定三必一选
616-C：作品章节模型
```

同一「企划中」界面可并置两者，**不得**把章节规划字段并入作品设定四块，**不得**把设定块拆成章节表字段。

## 8. 旧字段处理原则

只写**产品层原则**，不做迁移方案、不写 canonical 键名最终实现。

### 8.1 总原则

- **旧字段不决定新模型**
- **可读兼容**（旧数据能展示或映射摘要）
- **新写入 canonical 键**等后续 **616-B-A** 实现卡再定
- **不复活旧六字段**为产品主结构

### 8.2 字段清单

| 字段 / 来源 | 616-B 产品层处置 |
|-------------|------------------|
| `metadata.settings`（背景设定） | legacy；语义融入「时间与地点」时只读参考；不作新写入目标 |
| `metadata.characters` | legacy 表单块；不复活；新内容写「人物与关系」描述块 |
| `metadata.timeline` | legacy；新内容写「时间与地点」 |
| `metadata.relationships` | legacy；并入「人物与关系」语义 |
| `metadata.plotStructure` | legacy；新内容写「事件与情节」 |
| `metadata.worldBuilding` | legacy 别名；冻结 |
| `Proposal.coreSetting` | legacy 自由文本；**不**作为新设定四块之一；可不迁移 |
| `Proposal.innovation` | legacy；creative-v2 已降级；不进入作品设定 |
| `metadata._creativeNotes` | 创意组过程痕迹；**不**等同于作品设定；可只读带入企划参考 |
| `metadata._workExpectation` | 作品基础信息；**不属于**作品设定四块；616 宪法 §2.1 与梗概并列 |
| WorldBuilding 线（Character / TimelineEntry / CreativeFlow 表） | 616 §4 冻结；遗留资料只读；**不**包装为三必一选 |

### 8.3 与 616-A 的衔接

- A1：Tab「遗留资料（只读）」继续，直到 B 实现新设定 UI 后另议裁切
- A2：梗概读写与 `description` / `metadata.synopsis` 双轨**不受** B 草案影响
- B 实现前：**禁止**新功能向旧六字段写入
