# 0608-ux-interaction-model.md — 交互层级分离规范

> **文档角色**：定义 novel-writer 前端交互的层级分离原则。五部门所有页面的按钮、入口、操作必须遵循此规范。
> **优先级**：P1 — 新 Commit 实施前的 UX 宪法。
> **关系**：落实 `0608-amendment-decision-separation.md` 的页面与按钮层规则；补充 `0608-overall-architecture.md` §2（前端架构），替代 `0608-frontend-planning-workspace.md` 中的按钮散落描述。
> **状态**：Draft v1（2026-06-10，Hermes 协作产出）

## §0 核心原则

### 上位依据

本规范是 `0608-amendment-decision-separation.md` 的具体 UI 落地文件。

若本文中的按钮映射、页面职责或操作位置与修正案冲突，以修正案为准。

### UI 文案

列表对象名与工作区状态分开显示：

| 部门 | 列表对象名 | 工作区 |
|------|-----------|--------|
| 创意组 | 创意作品 | 构思中 / 已完成 |
| 企划课 | 企划作品 | 待企划 / 企划中 / 已完成 |
| 创作室 | 创作作品 | 待创作 / 创作中 / 已完成 |
| 编审部 | 审阅作品 | 待审阅 / 审阅中 / 已完成 |
| 文集库 | 文集作品 | 待归库 / 已归档 |

只有“构思中 / 企划中 / 创作中 / 审阅中”四个工作区允许进入可写详情页或编辑器。其他工作区进入详情页时默认只读。

### 最高原则

> **流程决策的对象是该状态下列表中的某个条目。**
> **内容决策的对象是作品详情页的内容。**
>
> **两者区隔，互不交叠。**

```
                    流程决策                            内容决策
                 ────────────                      ────────────
        对象:    列表中的条目                       详情页的内容
        问题:    "这个条目下一步去哪？"              "这个内容写得够不够好？"
        动作:    提交 / 放行 / 退回 / 暂存           保存 / 编辑 / 补充 / 删除
        结果:    条目在列表间移动                   内容发生变化，条目不移动
        发生:    只在列表页                         只在详情页
```

### 三层定义

```
┌─────────────────────────────────────────────────────┐
│  Tab（L1/L2 导航）                                    │
│  只筛选、只展示。                                      │
│  永远没有任何可执行动作按钮。                            │
│  点击 Tab = 改变列表的过滤条件。                          │
└─────────────────────────────────────────────────────┘
                        ↓
┌─────────────────────────────────────────────────────┐
│  条目列表 — 流程决策（对象 = 该条目）                    │
│  每个条目后面的按钮决定该条目的流程去向。                   │
│  按钮取决于：当前部门 + 当前工作区 + 当前 status。           │
│  按钮的语义：进入下一阶段 / 退回本阶段 / 暂存。              │
│  操作结果：条目在列表之间移动。                           │
└─────────────────────────────────────────────────────┘
                        ↓ 点击"完善"/"继续"
┌─────────────────────────────────────────────────────┐
│  详情页 / 编辑器 — 内容决策（对象 = 作品内容）             │
│  只有保存。只有编辑。                                     │
│  没有任何阶段转换按钮。                                   │
│  保存 ≠ 完成 ≠ 放行。                                   │
│  操作结果：内容变化。条目在列表中的位置不变。                 │
└─────────────────────────────────────────────────────┘
```

### 两个维度

| 维度 | 决策对象 | 决策问题 | 动作 | 发生位置 |
|------|---------|---------|------|---------|
| **流程决策** | 列表中的某个条目 | "这个条目下一步去哪？" | 提交 / 放行 / 退回 / 暂存 | 列表页 |
| **内容决策** | 详情页的作品内容 | "这个内容够不够好？" | 保存 / 编辑 / 补充 | 详情页 |

**两个维度的操作永不混合。** 详情页里不出现流程按钮，列表页里不出现内容编辑入口。

## §1 五部门完整映射

### 1.1 创意组

```
Tab: 创意组
  ├ 素材         ← 特殊，不适用三工作区
  ├ 作品构思中    ← CreativeFlow 列表
  └ 提案停留      ← Proposal(status=created) 列表
```

#### 素材 Tab

无条目级操作按钮。纯浏览/导入入口。

素材类型：外来参考 (FileReference)、灵感碎片 (Scrap, source=creative)、AI 搜索。

```
素材条目:
  无流程按钮
  点击条目 → 查看详情（只读）
```

#### 作品构思中 Tab

```
条目: 讨论标题 + 创建时间
按钮: [继续构思]  [✨ 提炼为提案]
        ↓              ↓
   进入讨论详情     生成 Proposal(creating)
   (CreativeFlow)   → 自动转至"提案停留"
```

#### 提案停留 Tab

```
条目: 提案标题 + 梗概摘要 + 创建时间
按钮: [✅ 提交企划课]  [📂 暂存]  [↩ 退回构思]

  提交企划课 → Proposal 放行，触发企划课"待处理"可见
  暂存       → Proposal.deletedAt = now（软删除）
  退回构思   → created → creating（部门内退回 ✅ F-001 合规）
```

**提案停留 Tab 是创意组唯一的"流程决策"入口。** 素材和构思中没有流程决策。

---

### 1.2 企划课

```
Tab: 企划课
  ├ 待企划    ← Proposal(status=created) 列表
  ├ 企划中    ← Project(status=planning) 列表
  └ 已完成    ← Project(status=planned) 列表
```

#### 待企划 Tab

```
条目: [Proposal] 提案标题 + 来源
按钮: [📥 接收入企划课]

  接收入企划课 → 创建 Project(planning)
                → submittedToPlanningAt = now
                → Proposal 标记为"已接收"
                → 新 Project 出现在"进行中"列表
```

**只有一个按钮：接收入企划课。** 不处理就是保持此状态（自然搁置）。

#### 企划中 Tab

```
条目: [Project] 作品标题 + 元数据完成度
按钮: [📝 完善作品规划]  [✅ 完成企划]

  完善作品规划 → 进入 WorkDetailPage(?from=planning)
                只有 [保存] 按钮
                不改变 Project.status
                保存后回到此列表

  完成企划     → planning → planned
                → 设置 greenlitAt = now
                → 条目移入"已完成"列表
```

**关键**：详情页（WorkDetailPage?from=planning）内**没有任何"完成企划"或"放行"按钮**。用户必须保存退出后，在列表条目上点击"完成企划"。

#### 已完成 Tab

```
条目: 作品标题 + 企划完成时间
按钮: [🚀 放行创作室]  [↩ 退回规划]  [📂 暂存]

  放行创作室 → 保持 planned 状态不变
              → 写入 metadata._releasedToStudioAt
              → 创作室"待处理"可见
              → 本条目标记为"已放行"

  退回规划   → planned → planning（部门内退回 ✅）
  暂存       → Project.deletedAt = now
```

**注意**：`planned` 状态同时出现在企划课"已完成"和创作室"待处理"。这是 0608 模型的设计意图——同一状态在不同部门有不同含义。

---

### 1.3 创作室

```
Tab: 创作室
  ├ 待创作    ← Project(status=planned) 列表
  ├ 创作中    ← Project(status=writing) 列表
  └ 已完成    ← Project(status=written) 列表
```

#### 待创作 Tab

```
条目: 作品标题 + 企划完成时间
按钮: [✍️ 开始创作]

  开始创作 → planned → writing
            → writingStartedAt = now
            → 条目移入"进行中"
```

**只有一个按钮**。不操作就是保持 planned。

#### 创作中 Tab

```
条目: 作品标题 + 当前字数 + 章节进度（如 8/30）
按钮: [✍️ 继续写作]  [🏁 作品已完成]

  继续写作   → 进入 WritingEditorPage
              只有 [保存] 和 [保存并标记当前章完成]
              不改变 Project.status
              保存后回到此列表

  作品已完成 → writing → written
              → workCompletedAt = now
              → 条目移入"已完成"
```

**关键**：编辑器内没有任何"作品已完成"按钮。用户保存退出后，在列表上做流程决策。

#### 已完成 Tab

```
条目: 作品标题 + 总字数 + 完成时间
按钮: [🔍 提交审阅]  [↩ 退回写作]  [📂 暂存]

  提交审阅 → written → 保持 written
            → submittedToReviewAt = now
            → 编审部"待处理"可见

  退回写作 → written → writing（部门内退回 ✅）
  暂存     → deletedAt
```

---

### 1.4 编审部

```
Tab: 编审部
  ├ 待审阅    ← Project(status=written, submittedToReviewAt IS NOT NULL)
  ├ 审阅中    ← Project(status=reviewing) 列表
  └ 已完成    ← Project(status=reviewed) 列表
```

#### 待审阅 Tab

```
条目: 作品标题 + 总字数 + 提交时间
按钮: [🔍 开始审阅]

  开始审阅 → written → reviewing
            → 条目移入"进行中"
```

#### 审阅中 Tab

```
条目: 作品标题 + 审阅进度
按钮: [🔍 继续审阅]  [✅ 审阅完成]

  继续审阅 → 进入 ReviewDetailPage
             只读分析 + 批注
             不改变状态

  审阅完成 → reviewing → reviewed
            → 条目移入"已完成"
```

#### 已完成 Tab

```
条目: 作品标题 + 审阅完成时间
按钮: [📚 文集入库]  [↩ 退回审阅]  [📂 暂存]

  文集入库 → reviewed → archived
            → archivedAt = now
            → 文集库可见

  退回审阅 → reviewed → reviewing（部门内退回 ✅）
```

---

### 1.5 文集库

```
Tab: 文集库
  ├ 待归库    ← Project(status=reviewed) 列表
  └ 已归档    ← Project(status=archived) 列表
```

#### 待归库 Tab

```
条目: 作品标题 + 审阅完成时间
按钮: [📚 归库]

  归库 → reviewed → archived
        → archivedAt = now
```

#### 已归档 Tab

```
条目: 作品标题 + 归档时间
按钮: [👁 查看]  [📥 导出 Markdown]

  查看 → WorkDetailPage(?from=library)
         只读模式，无编辑入口

  导出 → 下载 .md 文件
```

文集库不需要"已完成"Tab——`archived` 本身就是终态，所有已归档作品都在"已归档"中。

## §2 冻结项对照

本规范通过"关注点分离"根治了多个 0608 冻结项：

| 冻结项 | 原问题 | 如何解决 |
|--------|--------|---------|
| **F-004** 全局线性推进器 | StageTransitionModal 全局 N→N+1 链 | 每个部门独立按钮，无全局组件。列表按钮由部门+工作区+status三元组决定，不依赖 NEXT/PREV_STATE |
| **F-008** "一键进入编辑器" | planned→startWriting→navigate 三合一 | "开始创作"是创作室待处理列表的按钮。企划课放行后作品停留在创作室待处理，由创作室独立触发 |
| **F-009** planned→writing 直接端点 | 企划课 Tab ④ 直接开始写作 | 企划课条目不再有"开始写作"按钮。创作室的开始创作在创作室自己的待处理列表触发 |
| **F-010** StageTransitionModal | 全局阶段推进组件 | 全部废弃。每个按钮独立实现，内聚于所在部门上下文 |
| **F-007** "正式立项"文案 | "正式立项"隐含联通 | 企划课按钮改为"完成企划"，放行按钮为"放行创作室"，语义分离 |
| **F-005** 三选一混合语义 | 确认完成=放行合一 | 列表中"完成企划"（planning→planned）和"放行创作室"（planned 不变）是两个独立按钮 |

## §3 详情页约束

### 3.1 详情页只有这些操作

| 详情页 | 操作 | 说明 |
|--------|------|------|
| WorkDetailPage(?from=planning) | [保存] | 保存所有编辑。不改变 status。 |
| WorkDetailPage(?from=writing) | 只读侧栏 | 写作辅助参考。 |
| WorkDetailPage(?from=library) | 只读 | 已归档作品查看。 |
| WritingEditorPage | [保存] [保存并标记当前章完成] | 不改变 Project.status。 |
| ReviewDetailPage | [保存批注] | 批注可随时保存。不改变 status。[审阅完成] 是流程决策，位于编审部进行中列表条目上，详情页不出现。 |

### 3.2 详情页永远没有这些

```
❌ "提交企划课"     — 流程决策，属于提案停留列表
❌ "完成企划"       — 流程决策，属于企划课进行中列表
❌ "开始写作"       — 流程决策，属于创作室待处理列表
❌ "作品已完成"     — 流程决策，属于创作室进行中列表
❌ "放行创作室"     — 流程决策，属于企划课已完成列表
❌ "文集入库"       — 流程决策，属于编审部已完成列表
❌ 任何状态下拉框   — 状态由列表按钮驱动，不在详情页修改
```

## §4 按钮的视觉层级

每个条目最多 3 个按钮。布局建议：

```
┌──────────────────────────────────────────────┐
│ 《仙道苍穹》                                   │
│ 42,000 字 · 章节 12/30 · 2026-05-10           │
│                                               │
│          [✍️ 继续写作]  [🏁 作品已完成]         │
└──────────────────────────────────────────────┘
```

按钮层级：

| 位置 | 视觉 | 语义 | 示例 |
|------|------|------|------|
| 主按钮（左/第一） | 强调色/填充 | 推进流程 | [提交企划课] [接收入企划课] [开始创作] [作品已完成] [放行创作室] |
| 次按钮（中） | 边框/幽灵 | 进入详情页 | [完善作品规划] [继续写作] [继续审阅] |
| 危险/中性（右） | 灰色/红色 | 退回或暂存 | [退回构思] [退回规划] [📂 暂存] |

## §5 "只增不减"与详情页

详情页内的编辑操作遵循"只增不减"原则（详见 `0608-supplement-creative-discovery.md` §2）：

```
详情页内:
  ✅ 新增角色 / 补充角色信息
  ✅ 新增章节 / 修改章节正文
  ✅ 新增时间线条目
  ✅ 补充元数据字段
  
  ❌ 删除角色（隐藏按钮或二次确认）
  ❌ 覆盖核心梗概（完成企划后锁定）
  ❌ 删除已立项的章节
  
  [保存] → 只保存内容修改，不改变流程状态
```

## §6 实施优先级

### P0 — 任何新 Commit 前必须遵循

```
□ 详情页禁止出现阶段转换按钮（如果有，删除）
□ 条目列表必须有操作按钮（如果没有，添加）
□ Tab 点击只过滤列表，不触发任何操作
```

### P1 — 创意组 P4 实施时

```
□ 提案停留列表 + 三选一按钮
□ 作品构思中列表 + [继续构思] [提炼为提案]
```

### P2 — 后续 Commit

```
□ 企划课待处理/进行中/已完成列表 + 对应按钮
□ 创作室待处理/进行中/已完成列表 + 对应按钮
□ StageTransitionModal 逐步废弃
```
