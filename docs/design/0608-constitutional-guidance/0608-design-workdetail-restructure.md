## §1 新旧对照

```
旧 Tab                         新区
─────────────────────         ─────────────────────
setting (WorldBuildingPage)   创作资料（角色/时间线/心流）
chapters (章节列表)            作品章节（梗概内联）
metadata (ContentMetadataCard) 作品元数据（标题+梗概+字段面板）
(无)                          作品正文（预览+写作入口）
```

## §2 四区设计

### 页面级编辑态

WorkDetailPage 必须采用“只读参照态 → 显式编辑态”的双态模型。

默认进入页面时只读展示：

- 作品元数据
- 作品章节
- 作品正文预览
- 创作资料

默认态只显示页面级强指令：

```text
编辑作品详情
```

点击后才进入内容编辑态，并启用分区编辑入口：

- 编辑作品元数据
- 编辑作品章节
- 编辑正文 / 进入正文编辑

编辑态页面级动作：

- 完成编辑
- 取消编辑

页面级“完成编辑”只表示结束本次详情页编辑会话；不替代各分区保存，不触发流程推进。

### 作品元数据

- 顶部突出显示标题 + 作品梗概（最高级必填字段）
- **work.synopsis 为真相源**：metadata.synopsis 是当前存储位（legacy），description 仅作兼容回退
- 两处都存在且不同时显示提示，标注将来会统一
- 下方为选填字段面板 + ContentMetadataCard
- 编辑入口：ProjectMetadataPanel
- 编辑态下保存确认：保存元数据 / 取消元数据修改

### 作品章节

- 章节列表：第几章、章节名、章节梗概 **内联可见**（默认展开，可收起）
- 保留编辑标题、上下移动
- 保留"写作"跳转按钮
- “章节规划”是 1.0 继承口径，新 UI 和文档口径统一改为“作品章节”
- 编辑态下保存确认：保存章节 / 取消章节修改

### 作品正文

- 每章字数、状态、正文前 200 字预览
- "编辑正文"或"进入正文编辑"按钮跳转 WritingEditorPage
- 正文按章节正文编辑器保存机制确认，不纳入详情页总保存
- 编辑是内容决策，不触发流程推进

### 创作资料

- WorldBuildingPage（角色/时间线/创意心流）
- 明确标注"创作资料"，不等同于作品元数据

## §3 流程决策移除

**WorkDetailPage 不再承载任何流程决策按钮。** 已从页面移除：

- PlanningActions / StudioActions / EditorialActions / LibraryActions / GraveyardActions
- 文集归属选择器（CollectionPickerModal）
- resolveDepartment / deptCtx 流程决策推导逻辑

页面只保留内容动作：返回、Tab 切换、编辑元数据、章节管理、进入写作。

## §4 可写权限（按状态分 Tab）

| 状态 | 元数据 | 章节 | 正文 | 创作资料 |
|------|:---:|:---:|:---:|:---:|
| draft（构思中） | ✅ | ✅ | ✅ | ✅ |
| planning（企划中） | ✅ | ✅ | ❌ | ✅ |
| writing（创作中） | ✅ | ✅ | ✅ | ✅ |
| reviewing（审阅中） | ❌ | ❌ | ✅ | ❌ |
| 其他 | ❌ | ❌ | ❌ | ❌ |

补充约束：

- 上表只定义哪些分区允许进入编辑态。
- 即使状态允许可写，默认页面仍为只读参照态。
- 必须先点击“编辑作品详情”，再启用对应分区编辑动作。
- 审阅中允许正文审阅、批注、修订建议等正文相关内容动作；元数据和章节原则上只读。

## §5 字段兼容策略

- 梗概真相源：`work.synopsis`，存储位 = `metadata.synopsis`（legacy）→ `description`（fallback）
- 远期迁移目标：Project 表新增独立 `synopsis` 字段
- metadata.synopsis 更名或废弃后，`getWorkSynopsis` 只需调整读取源
