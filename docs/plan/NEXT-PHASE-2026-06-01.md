## 二、缺失的关键链路

虽然核心路径能走通，但有几个**关键缺口**让 2.0 还不能真正日常使用：

### 缺口 1：状态不会流转

作品从创建到完成，需要经过 `draft → planning → writing → reviewing → completed`。当前：
- 详情页操作栏按 status 显示不同按钮
- 但没有"推进到下一阶段"的入口
- 用户在创作室写完章节后，不知道怎么把作品状态从 `writing` 改成 `reviewing` 再到 `completed`
- 阶段过渡时的决策（继续/回退/暂存）没有 UI

**影响：** 作品卡在一个阶段出不去，管线的"流"没有真正形成。

### 缺口 2：没有"移入暂存"的入口

TASK-016 做了 shelve 的 API 和作品暂存列表，但在 `WorkDetailPage` 和 `ProjectCard` 上**没有"移入暂存"按钮**。用户没法把不想要的作品放进暂存。

### 缺口 3：没有"完结归档"的终点

作品最终应该能归档到文集库。当前：
- `completed` 和 `archived` 状态存在
- 但文集库页面是空的
- 作品完成后没有归宿

---

## 三、推进策略

### 原则

1. **先闭环，再丰富** — 先把"创作→流转→完成→归档"整条管线走通，再考虑锦上添花的功能
2. **不做大模块** — 编审部（连续阅读器/快照/审阅清单）是重大模块，不塞在管道闭环里，留作独立阶段
3. **旧页在收敛前清理** — 当旧页面与新功能确定重复时再删，不提前清理
4. **提交整理穿插** — 代码整理作为每一步的自然收尾，不单开时段

## 四、具体安排

### 第一步：管线闭环（P0，建议 1 张卡）

**目标：** 让作品能在五阶段之间顺畅流转，并支持随时移入暂存。

**范围：**

| 模块 | 说明 |
|------|------|
| 详情页推进按钮 | `WorkDetailPage` 操作栏中，根据当前 status 显示"进入下一阶段"按钮 |
| 阶段过渡确认 | 点击推进时弹出四决策点：继续 / 回退 / 暂存 / 取消 |
| 移入暂存入口 | 在详情页操作栏和 `ProjectCard` 菜单中加"移入暂存"按钮 |
| 状态降级 | 允许从当前阶段回退到上一阶段（如 writing → planning） |

**关键行为：**

```
当前位置：/work/:id

draft:      [推进到企划课] [移入暂存]
planning:   [推进到创作室] [回退到创意组] [移入暂存]
writing:    [推进到编审部] [回退到企划课] [移入暂存]
reviewing:  [推进到已完成] [回退到创作室] [移入暂存]
completed:  [归档到文集库] [移入暂存]
```

**阶段过渡弹窗：**
```
将作品「XXX」从 创作中 推进到 编审部？
─────────────────────────────────────
[继续推进]   [回退到企划课]   [移入暂存]   [取消]
备注（可选）: [____________________]
```

**工作量预估：** 中小卡（后端 API 小改 + 前端操作栏扩展 + 弹窗组件）

---

### 第二步：文集库（P1，建议 1~2 张卡）

**目标：** 已完成和已归档的作品有归宿，支持文集管理和导出。

**范围：**

| 模块 | 说明 |
|------|------|
| 文集库列表页 | `/library` 显示已归档/已完成作品，支持按文集筛选 |
| 文集管理 | 建文集、命名、归入/移出作品（复用现有 Collection 模型） |
| 导出功能 | 作品导出为 Markdown / 纯文本 |
| 详情页归档入口 | `completed` 状态的作品操作栏增加"归入文集"按钮 |

**工作量预估：** 1~2 张中卡（后端可能需要扩展导出功能，前端新建页面）

**注意：** 这是当初清理 Collection 前置依赖时埋下的伏笔——让 Collection 只出现在终点站。这一步就是兑现这个设计。
